## 使用方式与边界

打开工具栏「AI 助手」→「阅读与工作区」。标签暂存、原生分屏、正文提取、批注和资料检索不需要模型，也不要求开启 Agent。无痕及访客资料不能使用持久化阅读库。

1. 刷新标签列表，填写工作区名称并勾选 1–16 个标签，点击「暂存所选标签」。原标签保持打开；同工作区同网址不会重复暂存。填写已有名称后可以恢复该工作区，已打开的网址不会重复创建。
2. 勾选恰好两个尚未分屏的标签，点击「分屏所选两个标签」。布局与退出操作复用 Chromium 原生分屏。
3. 勾选一个来源并点击读取。网页只收集当前来源的正文；PDF 填写从 1 开始的页码，一次读取一页文字层。正文展示和保存上限为 32 KiB，不声明保存了超出范围的全文。
4. 在提取原文中选择文本并点击「使用选中的原文」，或填写原文中确实存在的引文，再填写批注并保存。保存后的引文在资料库中高亮；打开网页来源使用文本片段，PDF 使用页码。原站可能不支持文本片段定位。
5. 搜索覆盖已保存的标题、网址、正文、批注、引文、工作区名称和译文。资料加密保存，搜索时只在当前界面内存中匹配，不扫描浏览历史，也不额外建立明文索引。最多 128 条、总计约 2 MiB；归档是可恢复状态，不释放额度。
6. 网页翻译复用模型设置。先核对显示的服务地址和模型，再勾选发送授权，选择目标语言并翻译。响应必须是与原段落等长的字符串数组，失败不冒充已完成。译文仍须点击保存才进入资料库。

密码/表单页面、包含子框架的页面及 PDF 当前不能远程翻译。PDF 没有文字层、页码超界、来源导航变化、接口超时、存储不可解密或另一窗口已更新资料时，明确报错并保留原有资料。归档可恢复；本轮不提供永久删除或 OCR。

## 研究核查的复现入口

```bash
python3 apps/browser/scripts/audit-reading-research.py \
  --output .artifacts/reading-research-audit.json
```

脚本固定源代码提交，读取上游文件树并核对许可/权重是否存在，运行最小函数边界实验。不会安装上游 `.deb`、浏览器扩展或后台服务；不会把函数夹具当作模型效果。

- [MINIM 固定提交](https://github.com/yyyyhx/MINIM/tree/456c60b6fd47941d1e5849db573dbbcb488e3ae7)：仓库没有训练好的评分器权重，也未发现许可文件。规则层的 Keep/Abstract/Remove 与副本隔离可以复现；学习评分器的裁剪保留率、泄漏率和实际任务完成率尚无本机证据。
- [PhishLang 固定提交](https://github.com/UTA-SPRLab/phishlang/tree/6b7283854ef8a6edc73f945c1ce7e51b2e1dc4fd)：存在 MobileBERT safetensors 权重，未发现许可文件。原推理函数会跳过不足 128 token 的输入，并丢弃不足完整窗口的尾部。独立模型探针位于 `apps/browser/scripts/phishlang-model-probe.py`，只接受已核对的源文件摘要，使用本机权重和离线输入，不访问真实钓鱼网站。

模型探针以原窗口实现与补齐短输入/尾部的实现作对照。四份合成夹具只用于判断是否真实调用模型、窗口是否覆盖以及记录耗时，不用于估算准确率、误报率或选择默认拦截阈值。独立留出的真实标注数据、许可和跨平台性能都必须补齐后，才考虑产品接入。

### PhishLang 本机真实权重冒烟

使用上游 MobileBERT safetensors、PyTorch 2.4.0、Transformers 4.44.0，在 Mac ARM64 CPU 上固定两线程离线执行；没有安装上游扩展或后台服务。源文件和权重摘要保存在本机证据中。原始实现与补齐窗口的对照使用同一权重，结果如下。

| 合成输入 | token 数 | 上游模型调用次数 / 判断 | 补齐窗口后调用次数 / 判断 |
| --- | --- | --- | --- |
| short_article | 35 | 0 / benign | 1 / benign |
| short_login_lure | 82 | 0 / benign | 1 / phishing |
| long_article | 433 | 5 / benign | 6 / benign |
| long_login_lure | 462 | 6 / phishing | 7 / phishing |

短登录诱导夹具在原实现中被无条件放行为 benign，补齐窗口后才真正调用模型并得到 phishing。两份长输入均多覆盖了一个尾部窗口。这里只证实接口缺陷及修正方向；四份人工夹具不能证明模型达到任何准确率或误报率门槛。单次耗时包含冷/热状态差异，不作为产品性能结论。

重跑方式：在独立 Python 3.11 环境安装上述版本及 BeautifulSoup 4.12.3、NumPy 1.26.4，将固定提交的 `src/model` 和 `src/patched_parser_prediction.py` 放在本机实验目录，然后执行：

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python \
  apps/browser/scripts/phishlang-model-probe.py \
  --source /本机实验目录/phishlang \
  --output /本机实验目录/phishlang-model-probe.json
```

该实验未更改产品拦截策略；上游代码、模型权重、环境与原始输出均留在 Git 忽略的本机实验目录。

## 本轮问题与处理

1. **长正文被截成摘要长度**：移除正文对 2048 字符摘要清理上限的依赖，使用独立 32 KiB 范围。超过 6000 字符的末尾标记保存测试通过。
2. **工作区重复打开来源**：按保存来源去重，并识别加载中的可见 URL。原生测试及实际连续恢复均通过。
3. **复选框过大**：限制阅读区复选框和标签布局，DOM 回归与实机复核通过。
4. **编译及补丁完整性**：修正当前 Chromium 接口、测试夹具及安全缓冲区写法；补丁改为完整对象摘要导出。最终原生构建、脚本回归与仓库约定通过，失败日志保留。
5. **PhishLang 短输入放行、尾部遗漏**：固定源码和真实权重复现，并加入独立覆盖对照；没有直接改变产品拦截策略。
6. **钥匙串及固定签名启动问题**：最初认证由用户处理；已替换临时签名流程，并修复 GCSA 证书类别触发的启动断言。没有输入系统密码、修改钥匙串访问控制或用模拟钥匙串冒充实机验收。
