## 依据和范围

用户提供的 [cnBeta 报道](https://www.cnbeta.com.tw/articles/tech/1576534.htm)对应
[微软原始研究](https://www.microsoft.com/en-us/security/blog/2026/09/03/ascii-smuggling-crosses-over-from-ai-prompt-injection-to-phishing-evasion/)。
主要问题是 U+E0000–U+E007F 的不可见 Tags 字符：插进关键词可干扰匹配，编码隐藏指令可制造人与模型看到的内容差异。
[Unicode 官方说明](https://www.unicode.org/faq/languagetagging.html)同时指出标签字符也用于合法 emoji 序列，不能一律封禁。

旧版 C++ 与 Core TypeScript 的页面关键词匹配直接使用原始标题、正文；Agent 模型协议只拒绝部分 ASCII 控制字符，未专门处理 Tags 区块。既有来源范围、工具白名单、审批和敏感表单约束仍有效，但不能替代这道文本边界。

## 已实现

| 边界 | 本次处理 |
| --- | --- |
| 反钓鱼规则、本地分类模型 | 使用归一化文本副本匹配；加盐前后结果一致 |
| Agent 页面语义节点 | 保持原有读取上限，清理节点文本和标签副本 |
| Agent 的理解、规划、执行、修复和总结请求 | 在统一模型请求编码处过滤隐藏载体，覆盖 OpenAI-compatible、Anthropic、Gemini |
| 模型返回的操作参数 | JSON 解码后验证；含隐藏载体时拒绝，不偷偷改写参数、URL 或授权范围 |
| 隐私摘要与 Core 模型输入 | 先清理文本，再做敏感信息脱敏；不把还原出来的密钥重新发给模型 |
| 原生拦截页 | 增加“页面使用隐形字符干扰文本检测，已还原后检查”的原因说明 |

新增公共实现为 `chrome/common/aegis/security_text.{h,cc}`，由 Chromium 通用防护和 Agent Core 使用；TypeScript 对应 `packages/core/src/security-text.ts`。集成 overlay 与 canonical checkout 的 36 个受控文件已逐字节对齐。

具体策略：

- 删除完整 Tags 区块及 U+00AD、U+200B、U+2060、U+FEFF；不把隐藏 Tags 解码成指令。
- U+00A0、U+202F 转为普通空格，供文本匹配和脱敏使用。
- 精确保留英格兰、苏格兰、威尔士三个合法旗帜；伪造“黑旗 + 任意 Tags”不获豁免。
- 保留 ZWJ、ZWNJ、变体选择符与正常多语言文本，不采用“删除所有不可见 Unicode”的做法。
- 混淆原因权重为零，不能单靠该字符给网站定罪；仍由已有钓鱼证据组合决定拦截。
- 不修改原始网页、导航地址、浏览器授权范围或系统剪贴板策略；不添加云端逐页扫描、不新增密钥。
