# Codacy ESLint 子扫描器异常修复

## 根因与范围

Codacy 总质量检查成功时，ESLint 子扫描器仍可能已经中止。实际日志中的 `codacy/codacy-eslint:9.18.12` 使用 ESLint 8.57.0 与 `eslint-plugin-security-node` 1.1.4；其 `detect-unhandled-async-errors` 规则直接读取 `TryStatement.handler.type`，遇到合法的 `try/finally` 时因 `handler` 为 null 而崩溃。

使用该固定版本扫描仓库原有 253 个 JavaScript/TypeScript 文件，复现 15 个文件崩溃，其中包含 13 个 MJS 文件和两个浏览器本机 AI 脚本。将 27 处异步清理改为等待 Promise 的 `finally`，保留原有业务体、错误传播和清理顺序。修复后，包含新增回归测试的 254 个文件均完成扫描；压缩资源沿用既有 Codacy 排除规则。没有关闭安全规则或缩小 Codacy 扫描范围。普通规则诊断与扫描器崩溃分别处理，扫描完成不等于仓库所有历史问题已清零。

## 回归与验证

- 固定真实安全规则为开发依赖。新增负面对照先证明上游异常可复现，再检查全部 JavaScript/TypeScript 文件均可解析和完成规则扫描，并明确检查本机 AI 资源也在扫描范围内，防止空跑或静默关闭规则。
- 直接执行脚本中的真实函数，验证成功返回、原始拒绝、超时、计时器恰好清理一次，以及浏览器启动失败、Stagehand 创建失败、操作失败和清理失败时的资源清理顺序与异常。本机 AI 另覆盖数据库关闭、翻译模型与服务释放、推理会话释放，以及清理后继续返回分析结果。
- 下载验收的 CDP 请求使用固定回环 URL，只设置经验证的 1–65535 端口，拒绝 HTTP 重定向；回归覆盖端口边界与非法值。
- 桌面补丁 0315 与 Android 补丁 0306 分别基于各自既有脚本生成，保留平台已有差异。两个相关文件从各平台完整补丁序列回放，再应用新增补丁并逐文件核对摘要；该验证不是完整 Chromium 构建。
- Node 22.23.1 下完整 `quality:fast` 通过，包括 193 项核心测试、运行脚本自测、界面夹具、仓库合同与构建检查；105 项 CI 测试、38 项原型单元测试、静态检查和 WinRM 本地回环自测通过。
- PR #39 的 85 项源码及发行流程测试另行重跑通过。此次修复基于其合并后的主线，最终远端结果以对应提交的 GitHub 检查和 Codacy 子扫描日志为准。

本次修改脚本兼容性、同步补丁、回归测试和审计说明，未重新编译或安装 App，未启动付费候选构建。Ver 5.0 (208) 仍为新内核源码候选，三平台构建、原生验收及正式发行未完成。
