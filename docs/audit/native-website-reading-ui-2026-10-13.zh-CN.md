# macOS 与 iOS 网站设置、脚本和阅读界面验收

日期：2026-10-13。结论：本轮界面调整已完成本机和模拟器验收，可在固定测试应用中使用。macOS 为 Ver 5.0 (202)，iOS 为 Ver 7.0 (118)。验收完成时尚未提交、推送或发布；用户随后授权将这次 macOS/iOS 改动、报告和测试结果提交到 GitHub。本次没有操作 Windows 现有构建，也没有做 iOS 真机或分发验收。

## 使用方式

- 点击地址栏盾牌，查看当前网站的隐私状态、增强开关和适用脚本。网站设置自动保存，页面保留原状；需要重新运行时，使用明确的重新加载按钮。
- 在脚本卡片中查看执行状态、使用该脚本提供的菜单，或只在当前网站停用。全局启用状态和其他网站不受本站停用影响。
- 从设置进入「网站增强与脚本」和「阅读与 Markdown」。脚本列表先呈现，编辑器按需打开；新建入口保留 AI 编写、检查、试运行、授权启用流程。
- 从主菜单进入阅读库，或从盾牌直接将当前原始页面作为 Markdown 阅读。阅读器集中提供目录、查找、外观、助手及更多操作；阅读库中保存的全文可以重新打开。
- iOS 使用原生设置页、当前网站面板和阅读工具栏。本地文件选择与图片目录选择各有明确入口。

## 实际操作结果

macOS 验收使用独立的 `GCSA Aegis Acceptance` 配置，固定安装路径为 `/Users/lazy/Applications/GCSA Aegis Test.app`。

1. 在本地验收页面输入文字，切换复制开关后文字仍在，页面没有自动刷新。网站规则写入后可回读。
2. 已授权脚本在重新加载后执行；本站停用后重新加载恢复页面，脚本仍保持全局启用。重新启用本站后再次执行。脚本所属菜单能触发对应脚本，源码入口能定位目标脚本。
3. 原生设置页可读取既有脚本、网站设置和阅读库；搜索 Markdown 能找到阅读设置。主菜单入口收敛为设置与阅读库，既有 AI 助手入口保留。
4. 本地 Markdown、当前原始 Markdown 页面和保存的全文均可阅读。中文查找返回匹配，源码切换正常。外部图片和本地相对图片仍需按需授权，文档中的脚本字面量不执行。
5. 阅读器深浅色、约 857 × 708 CSS 像素的窄窗口、150% 缩放和 Tab 键焦点已实际检查，工具栏能换行。macOS 验收后恢复 100% 缩放和跟随系统的阅读主题。
6. macOS 实际打印保存 PDF，iOS 实际从文件选择器导入 Markdown 并生成 PDF。两份 PDF 均提取文字核对正文、代码和末尾标记，并渲染为图片检查；没有阅读工具栏混入正文，也没有发现正文截断。
7. 简体、英文和繁体核心界面已实际抽查。最终 macOS 英文脚本状态和文件导入朗读标签均正确；繁体设置与关于页面可用。iOS 最终 118 版再次完成繁体本地导入、深色正文和字号增大检查，正文不会随界面语言被改写。

PDF 人工验收来自 macOS 197 和 iOS 117；后续候选修复语言资源及界面标签，PDF 导出实现未改变。窄屏等人工证据来自 199；最终 202 另行复验语言与安装身份，并重新运行原生回归。证据版本分别保留，不把早期截图称为最终构建截图。
