# 本地 Markdown 首次打开问题与修复验收

日期：2026-10-14。此记录针对“第一次显示原文、刷新后才进入阅读页”的问题。

## 原因与修改

旧实现在导航开始时识别本地 Markdown，但明确排除了渲染进程发起的导航。拖放文件、从本地页面点击文件链接会经过这条路径，因此首次显示原文；浏览器刷新属于浏览器发起的导航，才进入自动预览。已在固定测试 App 中复现本地链接首次显示原文、刷新后正常渲染的前后差异；普通“打开文件”入口的对照测试可以正常首次渲染。

修复把本地文件识别移到主页面成功载入后，统一处理打开入口。只有 Chromium 已成功载入的本地文件才会再次读取；错误页、远程文件主机、子框架和非 Markdown 扩展不进入这条路径。保留 UTF-8、2 MiB 上限、导航身份与当前 URL 校验，以及不可信阅读框架的执行隔离。

新增三个原生浏览器回归测试，分别覆盖浏览器首次打开、页面链接首次打开和文件拖放，均检查无需刷新即可出现渲染后的标题。原有 HTML 禁止执行和外部图片默认阻止测试继续保留。
