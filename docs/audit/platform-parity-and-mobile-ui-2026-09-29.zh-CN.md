# 三端功能、品牌与界面适配评估

评估对象为 macOS ARM64、Windows x64、Android ARM64。结论：当前具备共用的 Chromium 内核、保护服务和 Agent 核心，但**尚未实现三端完整功能一致，也没有完成三端体验验收**。Android 070 原生测试 265/265 通过，不能抵消真机界面中发现的问题。Windows 新候选尚在构建，不能套用 macOS 的运行结果。

## 已确认的问题与本批修改

1. **手机保护中心按桌面比例缩小。** 真机访问 `chrome://aegis` 时，正文、复选框和操作按钮很小；源码缺少 `viewport`。073 补齐设备视口、手机页边距、正文与表单字号、长地址换行、触控面积和短屏弹窗滚动。宽屏继续使用原有居中布局，不把手机页面作为图片整体放大。
2. **Agent 的侧栏尺寸不能直接当作手机尺寸。** 桌面保留紧凑侧栏；触控设备提高输入字号与按钮高度，窄屏常用任务改为单列，标题及状态允许换行。Android 已有原生任务底部表单，本轮实际从菜单打开；详细任务和自动化仍是独立页面。
3. **版本显示与品牌资源不完整。** 系统 APK 已是 070，但原生“关于”及 `chrome://version` 主要显示内核号。073 将产品版本与 Chromium 内核版本分列，保留真实内核与诊断信息；手机版本页改为窄屏逐项排列，长路径可换行。
4. **存在 Chrome/Chromium 图标与文案残留。** 073 统一保护中心、版本页、首次引导、通知说明及相关登录推广图标，复用现有 GCSA Aegis 标识；关于、欢迎、通知等首要文案同步英文、简体、繁体。Google 账号标识、第三方版权与协议不应冒充为 Aegis 自有服务；本轮不作全仓关键词替换。其他系统弹窗和上游功能文案仍需按入口清单继续核对。
5. **保护中心摘要入口不可用却仍可点击。** Android 已禁用该处直接摘要按钮并增加三语说明，引导从网页菜单发起任务；这是准确表达现有能力，不是来源标签后端已经补齐。
6. **功能差异未向用户说明。** Android 任务页新增当前不支持窗口管理、工作区恢复和 BT 下载的说明，并说明定时检查需要浏览器保持运行。说明属于补救，不能算这些功能已经补齐。

这批源代码对应 073。071 的 CSS 风格检查失败、072 的通知插图遗留资源检查失败，均未交付；073 修复这些构建问题，没有关闭严格检查。构建、安装、截图和测试通过之前，不能把“代码已修改”写成“手机已修好”。

## 功能逐项对照

| 功能 | macOS / Windows | Android | 判断 |
| --- | --- | --- | --- |
| 普通网页、标签、收藏、历史、HTTP 下载 | Chromium 原生能力 | Chromium 原生能力，使用 Android 页面与系统文件权限 | 应保持操作结果一致；仍需各端端到端证明 |
| 跟踪拦截、钓鱼拦截、链接清理、Cookie/跳转清理、指纹保护 | 共用服务与内核修改 | 共用服务与内核修改 | 同代码不等于已验证；GPU、权限和生命周期须分别验收 |
| 挖矿脚本检测 | 当前为观察和提示 | 当前为观察和提示 | 三端都不能宣称强制拦截或限速 |
| Agent 规划、批准、取消、恢复、审计 | 共用核心，桌面侧栏 | 共用核心，原生输入表单与独立任务页 | 结果应一致，交互容器应不同 |
| Agent 标签、收藏、历史、下载工具 | 已有实现 | 已接共用及移动端标签接口 | 要逐项验收实际结果，不能只统计注册的工具名称 |
| 研究比较、保存研究结果 | 共用服务与页面 | 共用服务与页面 | 不等于桌面“工作区保存/恢复”；分开验证 |
| Agent 窗口工具 | 桌面实现 | `CanHandle` 排除窗口工具 | **缺口**；手机应表达为标签组/任务集合，不能直接照搬桌面窗口 |
| Agent 工作区保存、恢复 | 桌面实现 | 明确返回不可用 | **缺口，可以开发**；需要移动端标签组和状态恢复实现 |
| BT/磁力下载与增强面板 | macOS 已实现；Windows 的 `torrentSupported=false` | 未实现，使用原生下载界面 | **并非三端一致，可以开发**；需要 Windows/Android 下载后端及权限适配 |
| 保护中心直接摘要相邻网页 | 桌面有来源标签查找实现 | Android 的 `FindHttpTab` / `FindSummarySourceTabInModel` 返回空，不能沿用此流程 | **明确功能缺口**；菜单 Agent 摘要是另一个入口，不能混算为此功能通过 |
| 保护中心模型配置和本机调试连接 | 桌面有配置与本机连接入口 | 部分保护中心模型设置及调试区域隐藏；Agent 有独立模型配置 | **入口和能力不一致**；不能把隐藏入口当成适配完成 |
| 定时任务 | 随浏览器进程运行 | 随浏览器进程运行，另受 Android 后台限制 | 不承诺关闭浏览器或系统杀进程后按时执行 |
| 无痕中的 Aegis 页面/Agent | 受已有资料与隐私规则限制 | Android 页面明确要求常规资料，Agent 禁止无痕 | **实际范围不同**；需要统一产品规则和明确提示 |
| 文件上传、打开下载、打印/PDF、最终购买 | 有用户接管步骤 | 需 Android 文件选择器、分享/打印和权限 | 保留用户接管，不能为了“一致”绕过系统权限 |
| Google 登录/跨设备同步 | 存在上游入口，不等于服务已获可用资格 | 存在 Google 账号引导，不等于 Aegis 同步已可用 | 尚未验收；不能承诺 Aegis 自有同步或把 Google 服务改名冒充 |

核心证据来自 `aegis_browser_tools.cc`、`aegis_agent_service.cc`、`aegis_ui_handler.cc`、`aegis.ts`、Android 原生入口及版本页资源。窗口、工作区、BT 的差异有明确平台分支，并非仅凭外观推断。

## 图标与文案的适配边界

- macOS 的 App 图标、Windows 的 ICO/任务栏图标、Android 的普通/自适应/单色图标已经有各自资源；不能据此推断页面、引导和通知也都使用同一标识。此次漏项正来自不同资源入口。
- 品牌标识保持同一图形，按容器、安全区、浅深色和系统主题做适配；不要在手机上把桌面整块图文缩小。
- 版本页突出产品号；Chromium、V8、版权和第三方协议保留真实名称。初次登录的 Google 同步承诺要按真实可用服务审查，不能只把 Chrome 换成 Aegis。

## 应保留的平台差异

- **布局与操作习惯：** 桌面是鼠标、键盘、侧栏、多窗口；手机是触控、底部表单、独立任务页、系统返回；折叠屏根据实际窗口宽度适配，不能只判断操作系统名称。
- **安装、更新与权限：** macOS 签名/公证，Windows 安装与系统签名，Android APK 签名及系统安装授权不同。产品版本规则和更新真实性要一致，安装界面不能完全相同。
- **后台与文件：** Android 后台调度、文件授权和电池限制不同。跨端应统一任务结果、恢复状态及错误说明，而非承诺不存在的持续后台能力。

## 尚需补齐，而非“不可能一致”

1. 为窗口/工作区任务定义手机等价结果：标签组、工作集合保存与恢复，并用实际创建、回读、关闭、重启恢复验收。
2. 为 Windows 和 Android 实现 BT 后端，补齐文件选择、进度、暂停恢复、取消、校验与权限；在完成前只在支持的平台展示可执行操作，并在功能说明中列出差异。
3. 补齐保护中心在 Android 的来源标签绑定，或明确统一为菜单 Agent 摘要入口；目前直接摘要流程不能使用。统一模型配置的可发现入口与能力说明。桌面本机调试连接与手机 USB 调试属于不同用途，不应包装成普通用户必需的功能。
4. 统一三端资料/无痕规则，并确定 Google 服务、自有同步及后台自动化的真实支持范围；不能用文案换名代替功能交付。

## 执行与验收顺序

| 批次 | 工作 | 完成标准 |
| --- | --- | --- |
| A：本批基础适配 | 073 的保护中心、任务页、版本、首要品牌文案与图标 | 源码身份检查、构建、保留资料升级；手机实际可读可点，桌面不退化 |
| B：功能一致性补齐 | 工作区/窗口等价操作、BT、模型入口、资料范围 | 三端同一输入、预期结果和失败状态；每项独立记录实际支持情况 |
| C：集中验收 | 首次启动、菜单、设置、保护、任务、研究、收藏、下载、自动化、关于、更新 | Android 窄屏/横屏/折叠宽屏，桌面小窗/正常窗；三语、深浅色、系统字体放大、键盘/读屏；无裁切、假完成或死入口 |
| D：交付收敛 | 同一源代码批次的三个内部包、摘要、截图和差异清单 | 三端安装与原生操作均有证据；新增普通问题集中记录后决定下一批 |

构建耗时不应成为跳过体验验收的理由，也不应在 Windows 首次编译未完成时反复清掉已完成的对象缓存。当前 Windows 070 持续构建；073 适配需要随后增量同步并独立记录，070 结果不能冒充 073。
