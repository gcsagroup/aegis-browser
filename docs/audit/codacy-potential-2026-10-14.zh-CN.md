## 确认的问题和修复

1. **规范化 JSON 丢失特殊自有键。** 普通对象接收 `__proto__` 赋值时触发原型 setter，使包含额外内容的 JSON 和删去该内容的 JSON 得到相同规范化结果。改用无原型对象，并同步修复同一评估流程中 `corpus-eval`、`blind-protocol` 的相同实现。普通对象的排序结果不变；带特殊键的旧错误摘要不再视为有效结果。
2. **页面动作读取继承属性。** 快照节点可命中 `toString`、`constructor`、`__proto__` 等继承键，产生非字符串选择器或继承的目标地址。改为仅含自有条目的 Map，并检查选择器和目标 URL 类型。
3. **购物夹具产生错误导航。** 步骤编号命中对象原型成员时，会把函数文本拼进 URL。固定步骤改用 Map，未知编号仍走原有默认路线。
4. **两处日志正则存在平方级回溯。** 重复进程前缀，以及长空白后接 Unicode 换行的输入，会阻塞日志检查。改为分段查找进程前缀与状态后缀；正常 SIGTERM 只豁免单个合法日志头和单行消息。损坏的嵌套日志头继续计入异常，不放宽验收。
5. **请求日志并发写入且错误未接住。** `record` 脱离等待链写同一文件，测试中同时发生 13 次写入；磁盘错误还会成为未处理拒绝。改为串行写入，关闭流程等待记录完成，并在服务关闭后报告保留的错误。文件名由命令行指定本身不是漏洞，真实问题来自该写入点的调用方式。
