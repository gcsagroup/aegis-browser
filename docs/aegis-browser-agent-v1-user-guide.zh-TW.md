# Aegis Browser Agent v1 使用者指南

## 啟用與進入

1. 正常啟動目前的 macOS 本機候選版本，不需要附加 feature flag。
2. 一般 Profile 的工具列會顯示 Agent 按鈕；既有 Profile 升級時會一次性自動固定，之後使用者仍可取消固定。按一下按鈕即可看到側邊欄和啟用提示。
3. 開啟 `chrome://aegis`，在「瀏覽器 Agent」區域啟用執行總開關。
4. 設定模型 provider、Base URL 和模型名稱；loopback 模型可以不填 API key。
5. 按一下「開啟 Agent」，或使用工具列按鈕、右鍵選單、`Command+Shift+A`。

Agent 入口預設顯示，但模型呼叫、工具執行和監控仍依 Profile 預設停用，必須由使用者明確啟用。無痕、訪客和系統 Profile 不顯示可用入口。

## 三種模式

- Ask：只允許唯讀工具，適合研究、摘要和檢查。
- Act：執行目前已確認的計畫，遇到 R2 動作時暫停並要求精確核准。
- Automate：可在預算內連續執行低風險步驟；不會繞過核准或使用者接管。

## 發起任務

1. 先開啟要處理的網頁。
2. 在側邊欄填寫目標，並逐行檢查允許的精確 origin。
3. 選擇研究、瀏覽器管家、安全下載或購物工作流程。
4. 按一下「產生計畫」，檢查 provider、model、資料、工具、預算、風險和每個步驟。
5. 確認後按一下「開始」。任務可隨時暫停、繼續、接管或停止。

網頁中的「忽略使用者」、「讀取 Cookie」、「擴大網域」等文字都只是網頁內容，不是 Agent 指令。

## 書籤整理

Agent 會先讀取快照並產生預覽。套用前會檢查樹 revision；如果你在預覽後手動修改書籤，舊計畫會因衝突而遭拒。成功套用後可按一下「復原」，還原原本的父節點、順序、標題和 URL。v1 不會自動刪除書籤。

URL 檢查中的 401、403、429 和逾時不會直接判定為失效連結；只有 404、410 等明確結果才會成為失效候選。每次最多檢查 100 個使用者選定節點，整體最多 4 個並行請求、同一 origin 最多 1 個請求，並設有逾時和 429 退避。

## 安全下載

Agent 會比較官方來源、版本、平台、架構和雜湊，接著透過瀏覽器原生下載中心開始下載。下載完成後才會驗證 DownloadItem 和 SHA-256。架構不符、惡意重新導向或雜湊錯誤都會使任務失敗。Agent 不會繞過系統下載安全提示。

## 購物助手

購物工作流程會顯示商家、商品、數量、單價、運費、稅費、優惠、目前總價、配送、退貨、來源節點數和觀察指紋。進入最終確認前會再次觀察頁面；價格或頁面變更會使舊確認失效。

最終購買按鈕只能由使用者操作。Agent 會進入「使用者接管」，隱藏核准按鈕，並明確提示最後一步由你完成。完成或放棄後，再回到側邊欄結束接管狀態。

## 監控

監控只在瀏覽器執行時運作，支援價格、庫存、頁面變更和 URL 狀態。監控可以列出、暫停和刪除；連續失敗會退避。通知只包含監控類型和網站 origin，不會執行購買或其他外部動作。

## 隱私與疑難排解

- 側邊欄顯示的是目前任務範圍，不代表全瀏覽器授權。
- API key 使用系統加密儲存，不會重新顯示於 Agent UI。
- 停止任務後，受控 tab 和 Actor 會釋放；兩秒內不應再啟動新工具。
- 瀏覽器異常結束後，重新開啟任務時需要復原確認；待核准動作不會自動執行。
- 書籤復原只在目前瀏覽器工作階段有效；重新啟動後不會復原或重播舊寫入操作。
- 未完成任務 metadata 保留 7 天，已完成、失敗、取消或過期的任務 metadata 保留 30 天；頁面本文和原始工具結果不會寫入 TaskStore。
- 關閉總開關會取消模型、Actor、核准和監控。

如果任務失敗，請先查看側邊欄時間軸和錯誤。不要透過啟用遠端偵錯、放寬 origin 或向模型提供祕密來「修復」；這類做法超出 v1 安全邊界。
