# 现有 3X-UI 网页入口接线

日期：2026-11-17。开始基线：`152bd84ec569bf59d14475d9d0c6f78a7dee34f0`。
关联：阶段一 #98、平台验收 #141、用量 #159。后续审查完成后须对齐被接受的最新基线。

## 当前范围

使用现有 3X-UI 节点、签入构建的私有订阅描述和真实用量查询，复用既有网页站点开关、
Go REALITY 出站、本地入口、registry 与用量刷新协调器。账户后端 API 适配保持未启用。
独立账户 API / 服务端套餐账本的未完成草案已本地封存，不进入本轮 PR。

## 行为与约束

1. App 的网页 publisher 与额度页面共享同一个 `AccessSubscriptionUsageSession`。
   凭据、订阅源、允许的客户端和节点内容摘要仍由受保护构建输入绑定。
2. 网页创建入口前，必须完成同一订阅的有效额度查询与可用 REALITY 节点选择。
   缺失、无效、耗尽、到期、节点列表失败或身份不匹配均不回退到静态内置节点。
3. 未选择或未配置 3X-UI 时使用失败关闭 publisher；用量页显示订阅不可用，不改用未来
   账户 API 或把缺失数据解释为零余额。隐私页面继续隐藏普通用量。
4. App 不创建账户后端客户端，也不启动其余额轮询。现有独立测试和适配代码保留，
   不因此获得产品启用权。现有普通下载不接入新的账户后端。
5. 订阅和额度 HTTP 请求拒绝重定向，不能先跟随跳转再只校验最终 URL。
6. 保留既有 30 秒正常查询、后台停止、前台立即刷新、手动防抖与失败退避。
   3X-UI 未提供测量水位时继续明确时间未知，不把查询时间当作服务端测量时间。
7. 不重做另一条 iOS 架构任务负责的 HTTP / SOCKS 协议及端口切换，也不更改系统代理。

## 代码完成后的验证与交付

代码完成后统一执行受影响的原生单元、用量页面、站点开关、失败关闭和实际订阅重定向验证。
使用同一构建候选和输入摘要，完成 fresh Astra 独立只读复审，修复后重跑相关验证。
PR 的最终提交与 CI 单独核对，不以旧候选、跳过或零用例证明完成。

新增 `AccessThreeXUIWebEntryTests` 覆盖入口选择、同源节点与计数、额度失败/耗尽/外来
身份拒绝、已就绪入口在额度耗尽后通过既有健康检查失效，以及不依赖账户后端环境的用量页。
测试仅注入 lock 和 core，生产入口的参数与额度闭包仍由产品代码接线。实际 HTTPS 302 回归单独使用
`ThreeXUISubscriptionRedirectFixtureTests`：先为任务专用 Simulator 信任一个包含
`localhost` SAN 的临时证书，再运行
`python3 apps/ios/scripts/run-subscription-redirect-fixture.py --cert <cert> --key <key> --
xcodebuild test <项目和模拟器参数> -only-testing:AegisTests/ThreeXUISubscriptionRedirectFixtureTests`。
该 fixture 仅监听本机回环地址，断言两个订阅请求均拒绝跳转且目标访问次数为零。
未提供 fixture 时此独立用例显式跳过，不能据此报告 HTTPS 重定向验收通过；专用门必须
检查实际执行数、失败数与跳过数。证书不安装到主机或真机，也不进入产品构建。

真机前须等待独立的上游 iOS 架构与界面工作完成，并对齐其被接受代码与 CI 基线。

校验和执行独立能力测试。两种样本池分开统计；域名规则数不等于独立网站数。
