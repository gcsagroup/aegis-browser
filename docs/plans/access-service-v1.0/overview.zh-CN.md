**1. 产品定位与范围**

让普通用户在 Aegis 内为当前网站开启代理，由浏览器在后台完成服务接入、节点选择、续期、计量和故障恢复。日常操作只需要一个“当前网站使用代理”开关。

| 范围 | 当前设计 |
|---|---|
| 产品与平台 | Aegis 的 Chromium 桌面产品线，先在 macOS 实现和验收 |
| 作用对象 | 当前网站的明确域名，以及相同渠道、Profile 和受支持上下文中的匹配请求 |
| 本机入口 | HTTP 与 SOCKS5；实施先打通 HTTP，完整交付需要两种入口 |
| 后台服务 | 固定版本 Xray、自有或受控代理服务端、托管控制面、账户权益及用量账本 |
| 本期之外 | 系统 VPN/TUN、其他应用代理、多区域运营、付费购买流程；其他平台独立验收 |

关闭开关表示移除本功能的代理选择，恢复 Chromium 当前生效的原有连接设置。用户原本使用系统代理、扩展代理或 PAC 时，关闭后仍可能经过这些代理。产品文案应采用“未使用本服务代理 / 使用浏览器原有连接设置”。

**2. 渠道与用户体验**

| 渠道 | 用户可见能力 | 默认服务环境 |
|---|---|---|
| DEV | 简洁开关，以及独立调试视图：规则、ALLOW/BLOCK、订阅、手动节点、脱敏诊断 | local/development |
| Alpha | 同样具备简洁与调试视图，标明 Alpha 身份 | staging 内部租户 |
| Beta | 网站开关、用量、用户可读状态、Beta 标识和反馈入口 | staging；明确授权后可使用 production 的独立 Beta 租户 |
| Release | 网站开关、用量和必要状态 | production 正式租户 |

四个渠道使用同一套核心逻辑。调试能力由编译渠道和原生接口共同约束，Beta/Release 不注册通用规则编辑、订阅导入和手动节点接口。渠道数据、凭据与服务授权分别隔离；优化编译模式不决定产品渠道。

工具栏气泡提供当前域名、开关和简短状态。管理页依冻结顺序展示本期流量、网络状态、当前网站开关；已保存网站按域名列出开关和状态。账号与用量保留，节点参数等实现细节由后台托管。

| 用户动作或情况 | 设计行为 |
|---|---|
| 首次打开网站 | 沿用浏览器原有连接设置，保留正常安全防护 |
| 开启本站代理 | 后台准备身份、配置、节点和路由，显示“正在连接”；有效版本确认后显示已生效 |
| 首次开启失败 | 保留原已提交选择，显示“未能开启代理”及原因 |
| 已开启后断网、故障、欠额或退出账户 | 开关保留开启，连接状态独立显示不可用；受约束请求等待或失败 |
| 关闭或取消开启 | 本地提交关闭；离线、欠额或服务不可用时仍可操作，迟到结果不得重新开启 |
| 保存失败 | 明确说明未保存，不能承诺重启后保持 |
| 存在防护或管理限制 | 显示限制原因；网站开关不授予防护例外，也不解除管理限制 |

开关反映用户已提交的选择，连接状态反映服务是否可用。两者分开，避免将“已开启”显示成“当前连接一定成功”。界面适配英语、简体中文、繁体中文、宽窄窗口、浅深主题、键盘和屏幕阅读器。

**3. “当前网站”的精确定义**

网站选择由浏览器核验的当前导航产生，按渠道、Profile、StoragePartition 和规范化精确 host 保存。失败主导航也可以通过可信目标进行设置。

例如开启 `www.example.com` 后，在所属站点上下文中，同域的 HTTP、HTTPS、WS、WSS 及浏览器允许端口使用同一协议组。HTTP 跳转 HTTPS 不丢失选择；同域新导航和有可信归属的子资源、Worker、WebSocket 遵守该选择。

`login.example.com`、第三方 CDN 和其他域名不自动纳入。另一个顶层网站引用 `www.example.com`，也不自动继承本组。无可靠页面归属或不支持的协议需要明确说明覆盖限制。

网站协议组整体保存、发布、撤销与恢复。DEV/Alpha 的精确调试规则单独拥有和版本化，不能修改协议组中的单个成员；发生独立规则限制时，界面同时保留组选择和限制状态。

这里存在已识别的易用性风险：用户理解的“整站”可能包含多个域名。当前方案承诺明确范围内的代理选择，不承诺打开一个开关就能修复网站全部功能。关联域名支持属于后续需明确评审的产品范围。

**4. 技术架构与模块职责**

用户入口调用 Profile 级访问服务；服务准备并发布只读策略快照，由所属 NetworkContext 执行路由。命中代理的请求进入本 Profile 的本机 Xray，再由受控服务端转发到目标网站。控制面负责身份、配置、准入和用量，数据面负责转发及资源限制。

| 层次 | 主要职责 |
|---|---|
| 原生气泡 / 管理页 | 提交可信页面引用和开关意图，显示状态与用量；按渠道提供调试入口 |
| AegisAccessService | 复用现有 Profile 工厂生命周期，协调规则、身份、准备、切换和恢复 |
| 规则与请求归属 | AccessRuleStore、协调器、精确采集器和请求归属登记；提供原子发布、撤销、按流终止 |
| Network Service | 按已发布快照执行 DIRECT / PROXY / REJECT；处理连接池、缓存、预连接和上下文版本 |
| 本地代理管理 | ProxyCoreController 管理可信 Xray 资产、Profile 会话入口、进程和资源回收 |
| 托管控制面 | 自动访客登记、可选账户绑定、签名配置、短期租约、节点分配、撤销和用量推送 |
| 服务端数据面与账本 | 鉴权、实际字节计量、预算执行、速率限制、并发准入、幂等结算和对账 |

网络热路径使用 C++ 的本地只读快照；同步代理解析回调不等待网络、磁盘或跨进程确认。异步准备位于可暂停的派发入口。TypeScript 用于合同、界面及跨语言测试向量。

现有 AegisServiceFactory、CNAME 的 BrowserContext 分区和报告归属路由已有实现基础。P1 复用并验证其适用边界，补齐本服务需要的隔离与销毁处理。原有展示事件表有裁剪和域名归并，精确授权集合需要专用有界采集器。

**5. 后台接入、协议与故障恢复**

首次使用依次执行：读取有效缓存、必要时访问独立 bootstrap、取得身份和签名配置、校验授权与协议、验证候选、发布绑定、恢复允许派发的新请求。普通用户无需导入订阅或手选节点。

| 项目 | 冻结选择 |
|---|---|
| 主出站 | VLESS + RAW(TCP) + REALITY + XTLS Vision |
| 兼容出站 | VLESS + WebSocket + TLS，针对已约定的兼容需求单独验收 |
| 跨协议切换 | 受签名配置中的允许类别约束；只有运营明确授权且独立验证的类别才能使用 |
| 入口选择 | 自动选择后保持健康绑定，确认故障才切换，原入口恢复后不自动抢回 |
| 失败处理 | 区分本机断网、内核故障、入口故障、网站错误、满载和权益问题 |
| 身份和容量 | 同 VPS 多域名属于入口变体；真实部署、容量组、流量池和故障域分别登记 |

当前协议判断来自设计与资料核对。真实 target/SNI、版本、网络及时间窗口尚需绑定和实测，不能据协议名称承诺无法检测或长期抗 DPI。协议切换、长连接计量和额度截断同样需要真实证据。

此前讨论的 VLESS + XHTTP + TLS、VLESS + XHTTP + REALITY、NaïveProxy、Hysteria 2、TUIC、Trojan + TLS 保留为后续候选记录，尚未纳入 V1.0 必需交付，也没有本项目对比测试结论。

**6. 身份、隔离与用量**

默认提供受限安装级访客权益，并可显式绑定服务账户。同一渠道安装中的多个普通 Profile 使用各自的短期凭据，共享安装访客权益池；同一服务账户的用量在服务端跨其授权 Profile/设备累计。换节点或新建 Profile 不重置既有账户额度。

规则、秘密和运行状态按渠道与 Profile 隔离。无痕/Guest 使用独立临时上下文和短期凭据，退出不保留持久秘密；默认共享受限安装访客权益，使用服务账户须在临时上下文明确授权。退出账户会停止旧身份代理流并禁用本地凭据；回到访客需要明确选择。

用量以服务端实际双向转发字节为准，按冻结计量边界包含目标 TLS 数据，排除外层代理封装、专用控制面和独立运维探测。真实重试计量，直连和本地缓存命中不计。供应商 VPS 流量总账与个人用量分别核算。

| 事项 | 当前设计 |
|---|---|
| 显示 | 已用 = 上传 + 下载，最小显示单位 MB，自动切换 GB/TB |
| 额度 | 明确区分有限、无限和未知；未知或未同步不冒充 0 或无限 |
| 执行 | 中心余额预留和节点有界字节租约，传输路径执行耗尽/到期限制 |
| 同步 | 可见且活跃时约每秒更新，多个界面共享本 Profile 的一份订阅 |
| 成本与公平性 | 物理 VPS、租户和账户的限速、连接、并发与流量限制共同生效 |
| 账本恢复 | 重复、乱序、节点重启、切换和周期重置不重复扣减或回滚累计 |

Vision/splice 的适用快路径必须验证在途持续计量与预算执行。验证前使用满足计量合同的路径；不能满足时对应门槛阻塞。CPU、内存、网络队列、秒级推送和内核回收均有预算。

凭据使用系统加密能力保存；规则库和用量账本不收集原始 URL 查询参数、Cookie、表单内容或页面正文。诊断保留必要的脱敏数据，访问权限和保留周期按部署合同绑定。

**7. 必须始终成立的行为**

- 网站开关仅改变代理选择；安全防护和不可覆盖的管理限制继续生效。
- 已要求代理的请求在断网、节点故障、欠额或退出身份时等待或失败，保持原代理意图。
- 规则发布、网络切换、重启和旧回调不得造成错误路径复用；已发送的表单、购买或其他业务不自动重放。
- 调试 ALLOW 是明确范围的允许并代理；批量 ALLOW 保留手动阻断，单目标 ALLOW 可按合同解除。BLOCK 本地拒绝所选目标，并按流终止命中的在途请求。
- 关闭网站代理、取消准备以及本地调试阻断不能因服务不可用而失去操作能力。
- 凭据、用量和策略不跨 Profile/渠道串用；未知、部分覆盖、保存失败和未验证均需如实显示。
- WebRTC、WebTransport 等 UDP 场景不由 HTTP/SOCKS 支持自动推导为已覆盖；要求代理的上下文需要明确限制和独立验证。

**8. 实施顺序与验收**

| 工作单元 | 交付重点 |
|---|---|
| P0 | 固定实际源码、构建及环境；验证代理接入、已有代理组合、SOCKS 认证、按流终止、渠道身份和 Vision 计量风险 |
| P1–P2 | 复用 Profile 基础，补齐隔离；实现规则模型、匹配器、原子协调和恢复 |
| P3 / P3a–P3d | Xray 与真实主链路、托管接入和切换、调试/渠道隔离、计量额度及物理/账户资源控制 |
| P4–P5 | 精确请求归属、复杂上下文、联合策略发布、定向终止、竞争和撤销恢复 |
| P6 | 简洁网站开关、用量和错误状态；DEV/Alpha 调试界面及普通包接口隔离 |
| P7 | 补齐 SOCKS5、WS+TLS、OTR/Guest 和复杂请求的完整适用矩阵 |
| P8 | 最终候选补丁重放、四渠道构建、性能与故障回归、安装升级和回滚证据 |

| 门槛 | 达到后可以声明 |
|---|---|
| G0 | 固定基线原型的关键接入可行 |
| G1 | 在明确用户、规模和覆盖范围内，受控 Alpha 可试用 |
| G2 | 完整功能候选 / Beta，适用必需功能与性能验收通过 |
| G3 | 在已验证平台、规模和拓扑内可分发，最终包和项目发布要求通过 |

这些门槛是目标，当前没有本访问服务的通过结论。Alpha 部分场景通过只记对应子项，不代替完整 Beta 验收；G3 的技术分发条件也不自动证明付费运营已准备好。

初始性能目标包括：首次准备最多 15 秒，故障复核最多约 6 秒、确认后的切换最多 15 秒；用量从节点计入到可见 UI 的 p95 最多 3 秒、p99 最多 5 秒；无代理需求时 60 秒内回收空闲内核。平均体验、尾部时延、吞吐、总 RSS 和支持人数仍需要实际测量，完整约束见规范第 11 节。

测试分为合同、原生单元、真实浏览器、服务端集成、端到端、性能故障与最终包验证。每次绑定源码/补丁/内核/配置 hash、渠道、机器、网络、部署和实际规模。文档预览只能验证文档交互，不能授予产品发布资格。
