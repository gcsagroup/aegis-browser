## 一次点击授予什么

在站点菜单或主导航失败页提供同一个开关 **「本站打不开时自动重试」**。正常页面的说明是「先用当前连接打开本站和已知登录站点。页面打不开时，自动尝试用代理加载该页及其资源。」点击一个正常页面只登记授权，保留当前 WebView、登录态和连接。点击一个符合条件的失败页，同时恢复眼前这次导航。默认在本次浏览作用域内有效，用户随时可以关闭；私密授权随本次私密会话结束。

例如商城主页面正常，用户点一次后继续浏览。稍后跳到清单内的登录域，原连接上的主导航因 DNS 错误失败，浏览器自动尝试对该登录页代理恢复一次。成功后显示「登录页已通过代理打开」。若只有商城内的一张图片加载失败，主页面继续显示，不整页切换。单独打开一个未加入的域名，按它自己的既有规则选路。

**首版的选择单位是顶层页面。** 恢复后的页面资源随该页面的专用存储，可能包括第三方域名。这个影响范围必须在首次开启时可见。只获得「代理失败的精确目标」授权的产品模式，在同页分流验证通过前保持原连接；用户仍可明确选择现有的整页代理重试。精确成员决定哪些主导航有资格触发恢复，不能作为每个子资源的出口证明。

## 渠道与成员

| 构建渠道 | 每个站点组的精确 host 上限（含主 host） |
| --- | ---: |
| DEV | 128 |
| Alpha | 64 |
| Beta | 32 |
| Release | 16 |

以上为同一功能的容量约定。使用分支中的 `AccessReleaseChannel`；App 从构建产物读取渠道，注入 AccessKit。当前展示层从 `AegisFirebaseChannel` 解析，Fastlane 已有 `request.profile`，但 Release 配置和内部归档允许 Firebase 为 `disabled`。实现时由同一个构建 profile 写入独立的产品渠道字段，不能由遥测开关、网页、导入文件或运行时偏好放宽额度。缺失或未知按 Release 16 处理，调试面板继续遵守现有渠道门禁。

- 主 host 必计入且只计一次。对 HTTPS/HTTP URL 用分支的规范化精确 host 键去重后计数。子域独立计数，未提供清单时组中只有用户当前开启的主 host。候选来源限定为版本化的核定清单或用户对精确 host 的显式追加。探测建议留在候选区。
- 构造、导入、追加和发布共用一个上限检查。边界 N 可发布；第 N+1 个不同 host 令整次变更失败，并保留当前渠道仍合法的旧版。重复项不能占位。配置不静默截断，运行时不拆组绕过限制。
- 若以后保存普通模式授权，恢复时按当前渠道重新验证。高渠道遗留的超限组暂停自动执行，保留原数据供缩减并重新发布。显式强制代理或已经绑定的故障连接继续遵循既有失败关闭规则。私密组和诊断结果不落盘。
- 组大小只约束授权集合。一次开启 128 个成员只发布一份规则快照，不为 128 个 host 创建 WebView、存储、监听器或探测任务。专用存储仍按实际需要建立，沿用原有空闲回收策略。

## 分支接线

| 位置 | 具体改动 |
| --- | --- |
| BrowserKit 的 `BrowserTab` | 为开关提供「已提交的 HTTP(S) 主文档」或「此次失败的可信主导航快照」。在允许的页内导航、重定向和清洗后的替代请求上记录实际 URL 与方法，并与实际 `WKNavigation` 对应。匹配不到或遇到过时回调时只显示普通错误。 |
| AccessKit 的站点组 | 复用并发工作中的 `AccessSiteRuleGroup`、`groupID`、`generation` 和 `AccessHostStoreKey`。保留主 host、去重成员和作用域，把单一常量 16 替换为可信渠道的上限。核定清单只解析本次点击的组；未来扩大清单不自动扩大已发布快照。 |
| App 的 `AccessHostStoreCoordinator` | 单独保存已启用的自动恢复组。成员有权尝试恢复与 `intents[key] == .on`、入口已就绪、标签已绑定是不同状态。开启正常页面时不批量调用 `setProxyEnabled(true)`。在 `mainFrameFailed` 增加已授权的冷启动分支，与失败页点击共用一次准备、定向发送以及取消入口。组员因失败而激活属于执行状态，不能逐成员递增全局 `switchGeneration`，否则两个同时恢复的成员会使对方的票据失效。 |
| `AccessProxyEntryPublisher`、`AccessHostDataStoreRegistry` | 保留现有唯一的本机 CONNECT 入口、非持久专用存储、禁用 failover 和既有进程内出口。只为本次需要恢复的 host 准备和引用入口；相同 host 的同时失败可合并准备，每张标签票据分别消费。单个等待者取消只释放自己，不得使同代其他等待者失败。 |
| 失败页、站点菜单 | 都传入被点击的 tab。开启待命显示「已开启 · 当前使用原连接」；正在准备、已通过代理打开、入口暂不可用分别显示。只有对应恢复导航在代理绑定下达到约定进度才显示已打开。 |

现有分支的 `host(for:)` 允许取 `requestedURL`，失败回调允许回退到旧 `attempt`，且错误分类对 `NSURLErrorDomain` 主要采用排除法。第一批改动先修这三个点。还要把 `AccessProxyEntryPublisher.prepare` 中单个 waiter 的取消和共享 provision 的真正失败分开，再接入无人值守的自动恢复。[导航记录](../../../apps/ios/BrowserKit/BrowserSession.swift) · [协调器](../../../apps/ios/AegisApp/AccessHostStoreCoordinator.swift) · [入口发布器](../../../apps/ios/AccessKit/AccessProxyEntryPublisher.swift)

## 一次恢复如何完成

1. 以 `scopeID + isPrivate + groupID + generation` 固定点击时的授权；私密 scopeID 本身就是该次 privateSessionID。普通窗口按现有 scope 共享。组替换按预期版本一次提交，拒绝旧回调和旧清单覆盖新版本。多个组包含同一登录域时，撤销只移除该组贡献；最后一个有效授权和独立手动意图均消失时才释放对应绑定。不要用「第一个包含该 host 的组」决定撤销。
2. 在原连接上有可信的主导航失败，且命中当前授权组时，检查真实请求。首版允许无请求体的 GET/HEAD，保留 HEAD。只纳入明确的域名解析、无法连接、连接中断或超时等网络错误。设备已离线、取消、TLS/证书/ATS、HTTP 状态、重定向过多、挑战或登录提示均不给自动重试额度。对 POST、无法确定实际方法、携带不可安全恢复的凭据或提交上下文的请求，留给用户处理。
3. 对该失败创建或复用唯一操作。成功页点击不启动探测，冷入口首次失败时才准备，原有点击/准备预算为 15 秒。发送前再次核对标签、作用域、组版本、host、导航和失败 ID、入口实例和 generation。发送前消费一次额度，只恢复该标签的失败 URL。重复回调、重复点击和同 host 的其它标签不会产生连锁重载。用户手动开始一次新重试可生成新操作。
4. 若入口不可用，未绑定标签保留原存储、显示失败；此次恢复不再自动发送原连接请求。已绑定标签在入口故障后保持绑定并失败关闭。迟到的准备结果不得复活已关闭的组。新导航、停止、关闭标签、撤销、结束私密会话使相关待发票据失效。
5. 不迁移普通与专用存储间的 Cookie、DOM、表单及历史。即使代理成功，登录站仍可能要求重新登录。只在失败后的合格导航重建 WebView，正常页开关不触碰正在填写的表单。主导航换到另一个 host 时按其授权重新选存储。绑定标签继续遵循已有共享/解绑合同。

## 同页资源选择性代理

对于「主页面和图片仍从原网络加载，只有登录接口走 Access」，必须同时在代理入口和原连接源站拿到正向收据。当前的专用存储会将跨域资源送入同一入口，已有 WebKit 用例就同时收到了主页面与 CDN。Apple 的匹配和排除 API 都按域名后缀描述；共享存储上的其它 WebView 会使用同一配置。拒绝误入 CONNECT 的请求只能证明没有向远端发送，不能证明资源从原连接成功加载。[跨域资源用例](../../../apps/ios/Tests/AegisTests/AccessHostWebKitRouteTests.swift) · [I0 反例](ios-i0-capability-20261110.zh-CN.md) · [Apple 存储级代理接口](https://developer.apple.com/documentation/webkit/wkwebsitedatastore/proxyconfigurations-cdc1)

如果开发这项能力，优先在独立数据存储上验证 WebKit 的原生目标过滤，并在新 WebView 开始加载前完成配置。用受控端点分别验证成员、未加入的直属及更深子域、无关域、另一顶层页面、普通/私密、系统代理/PAC、已建立的 HTTPS 连接复用和撤销。成员走 Access、未授权目标走各自原路径，两侧都要有带本次标识的请求。仅通过部分情形，功能名称仍限定为上面的主导航恢复。首版无需引入可向任意目标直拨的本机中转、解密 HTTPS 或改造内核出口。

## 实施与验收

| 顺序 | 可观察的通过条件 |
| --- | --- |
| 1. 修正导航身份和错误分类 | 真正的页内 POST 失败不会被上一页的 GET 重试。未提交 host 不获授权。超时正例与 ATS、证书、离线、重定向循环反例各按约定处理。 |
| 2. 发布规则与容量 | 四渠道分别覆盖 128/129、64/65、32/33、16/17；主域重复、不同子域、超限替换、渠道降级、重叠组撤销、私密结束均验证。开启正常页时网络夹具记录零新增请求，专用存储零新增。 |
| 3. 一键完成真实恢复 | 一次点击开启；组内登录域的原连接主导航失败后，在同一标签收到经指定入口的唯一响应，组外顶层源站实际收到原连接请求。超时、旧回调、单等待者取消和入口故障均无静默直连。已绑定页面的第三方资源单独记录。 |
| 4. 可选诊断与回归 | DEV/Alpha 手动对核定探测终点检查。建议一批至多 3 host、总预算 15 秒、独立临时会话、无 Cookie/凭据、跨域跳转即停。已经要求代理的 host 跳过直连探测。结果只作建议。R 的挑战/地区限制单列，正常导航不等待双探。[R 判定合同](ios-access-blocked-site-regression.zh-CN.md#3-单站判定合同) |

设备与进程内出口验收沿用 U/K/D 的分项证据。2026-11-11 复核了已有 iOS 模拟器日志：同一专用存储上，跨域资源、后缀匹配的子域、另一顶层 WebView 使用该代理的三个反例均有通过记录（分支工作区 `.artifacts/ios-access-k-final/xcodebuild.log`）。

另编译了独立的本机源站/代理夹具，计划在 iOS 26.5 比较原连接、整存储代理、域名后缀和排除配置。新建模拟器在夹具启动时进入关机状态，重试仍未得到请求收据，本轮记 `NOT_RUN`。带前导点或星号的排除写法能否可靠表达精确 host 仍待验证；不将这些写法纳入首版合同。
