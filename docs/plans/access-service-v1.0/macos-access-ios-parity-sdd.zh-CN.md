# macOS Access 与 iOS 对齐规格

以 iOS [#173](https://github.com/gcsagroup/aegis-browser/pull/173) 合并提交 `27ee45a9` 的当前网站面板与额度行为为参照。macOS 在 fork `develop` 的 `f7314caf` 基线上接续既有实现，复用 [#145](https://github.com/gcsagroup/aegis-browser/pull/145) 的 Chromium 网站代理通路和现有账户查询。产品差异跟踪于 [#159](https://github.com/gcsagroup/aegis-browser/issues/159)，浏览器验收跟踪于 [#141](https://github.com/gcsagroup/aegis-browser/issues/141)。

## 需求与验收

| 需求 | 可观察行为 | 验收 |
| --- | --- | --- |
| 当前网站 | 从原生工具栏查看当前主机、代理开关、连接状态和可用的脱敏节点名称。网络失败页可在原标签点击「通过代理重试」。开启成功后同次导航完成，关闭后恢复浏览器原有连接。 | 测试同站页面、跨主机重定向、登录回跳、必要图片或 API，以及两个并存标签。核对真实内容和同次主文档代理路由。故障后保持失败关闭。独立打开同一资源、明确关闭或受策略保护时，按该请求自己的授权处理。保留禁止自动重发写请求的回归。 |
| 额度与节点状态 | 普通 Profile 的气泡和设置页显示一致的授权、上行、下行、剩余、总额、测量时间和适用的到期信息。显示可读容量和精确字节。区分未绑定、未开通、耗尽、过期、读取失败及旧数据。私密窗口不显示普通 Profile 的数据。 | 测试完整数据、未知测量时间、节点无到期、服务端到期、账户切换、无痕隔离与迟到响应。用已授权的真实测试节点或账户比对同一次计量样本。 |
| 刷新 | 额度区域可见时每 5 秒刷新，普通前台浏览时每 30 秒刷新。后台停止，回前台立即刷新。手动点击立即刷新，1 秒内合并，单 Profile 只允许一个在途查询。失败后间隔 15 秒、30 秒，成功恢复正常间隔。 | 用注入时钟验证时序，覆盖多窗口、气泡和设置页共享请求、在途切后台、切账户及销毁。真实浏览器用受控账户的请求时间记录核对可见、后台、手动和失败恢复。 |
| 服务端执行与恢复 | 浏览器显示服务端结果；节点执行同一账户、同一周期的计量、额度截止和到期截止。受控续额后刷新权益，原网站选择保留，并能再次重试。 | [#154](https://github.com/gcsagroup/aegis-browser/issues/154)、[#157](https://github.com/gcsagroup/aegis-browser/issues/157)、[#158](https://github.com/gcsagroup/aegis-browser/issues/158) 的可用服务端版本接入后，联合对账并实测转发中断、每日重置、续额与恢复。 |

在已加载的页面从工具栏开启代理时，等节点就绪和路由发布确认后重载一次。重载使用发起操作时的当前主机和完整页面地址，发起全新的 GET，避免缓存掩盖换路。关闭代理、切走标签、停止或开始新导航均可取消等待中已失效的重载。跳转前是 POST、需要重交表单或请求方式未知时，只保存用户的代理选择。失败页继续使用原有的重试入口。

## 实现顺序

1. 将现有 Chromium 补丁和 overlay 对齐当前 `develop`，保留已验证的付费节点传输回调。气泡走原生 Views，设置页走现有 Polymer 页面，网站权限由原生路由协调器处理。
2. 核对三处入口的状态一致性。失败页和工具栏向同一个原生网站路由发起操作，气泡和设置页复用同一 Profile 的额度和刷新状态。暂时读取失败时标明上次结果，读取每次复核原绑定；换账户、退出或绑定不可验证时清除原数据。计量来源和授权来源明确标示。
3. 用最终补丁生成 Chromium 候选，跑受影响 GN/Ninja 目标、账户传输与界面测试，再用实际浏览器完成受控故障站和额度场景。
4. 沿用 iOS 的原始 100 个 URL 与顺序，按原五组各 20 站试跑。只有一次用户代理操作、真实整页内容与同次路由日志都成立的行才计入首点成功。逐站保留首次结果和实际落地主机；需二次开启的站点单独记录，再按真实用户行为复测。验证码、登录限制、缺失路由证据和未跑各自记录。
5. 关联候选提交、Chromium 树、原生和浏览器日志。修复实际发现后重复对应场景，对最终候选执行独立只读审查和仓库质量门，更新 #159 与 #141。

历史 UI 候选的源码和独立测试可以作为回归输入。新候选的浏览器构建、真实站点和服务端行为按各自运行结果记录。
