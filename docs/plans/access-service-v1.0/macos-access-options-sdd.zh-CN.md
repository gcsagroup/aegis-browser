新增编译期产品身份 `aegis_access_product_channel`，取值为 `debug`、`alpha`、`beta`、`stable`、`unknown`，默认 `unknown`。另设编译期内部能力位 `aegis_access_internal_options`，默认关闭。它们进入生成的原生 buildflags，由 Browser 读取。构建身份与节点资源是否打包独立，Alpha 缺少节点时仍可提供内部配置页，并报告连接不可用。

Browser 使用同一个受信构建身份解析结果产生 Access 归属和内部能力。显式 `debug / alpha / beta / stable` 分别映射现有 `kDev / kAlpha / kBeta / kRelease`，由 `AccessChannelForCurrentBuild()` 返回；节点资源不能改变该归属。编译身份为 `unknown` 时保留现有 Chromium 与打包节点的兼容归属映射，但完整 Options 仍关闭。`AEGIS_DEV_LOCAL_NODE_ALLOWED = !is_official_build` 保留既有开发输入用途，不能授予完整 Options。

构建验证拒绝显式产品身份与 Chromium BETA / STABLE 等已知发布身份的矛盾组合。运行时发现这类矛盾时关闭内部能力、报告身份冲突，并保留 Chromium 明确的发布归属，不能降级到 DEV。节点资源的渠道必须与解析后的 Access 归属一致，缺失或不一致只使对应节点来源不可用。

| 编译身份和能力位 | Chromium 身份及其他输入 | 完整 Options |
| --- | --- | --- |
| debug / alpha，内部能力开启 | UNKNOWN 或一致的内部身份 | 开启 |
| debug / alpha，内部能力关闭 | 任意 | 关闭 |
| beta / stable | 包括 UNKNOWN、DEV、本地节点参数及内部能力误开 | 关闭，并在构建验证中拒绝矛盾配置 |
| unknown | 包括非官方构建、DEV 映射、运行时开关及配置文件 | 关闭 |
| debug / alpha | Chromium 明确报告 BETA / STABLE | 关闭，并报告构建身份冲突 |

CI 核对构建参数、生成的能力清单和包身份。运行时参数、Prefs、Options 导入和节点清单均不能提升该能力。受限构建仍运行项目需求定义的产品功能。

能力判定由 Browser 侧产生。入口展示、读取、写入、导入和运行时激活使用同一判定。Beta 的直接页面访问、旧内部配置和伪造消息均需进入对应的原生判定。

## 架构与状态

### 产品入口和 Options

工具栏当前网站面板继续使用现有网站、连接和失败状态。内部 Debug/Alpha 增加 Options 入口，配置页复用项目的 WebUI 资源、本地化、主题变量与可访问性模式。拟采用独立的受信 WebUI 页面，具体 URL 在实现接线时固定并纳入测试。

Options 分为界面、常规、导入导出、主题、内置 Profile、自定义 Profile、自动切换、日志、账号与用量、关于。账号和当前网站的产品入口继续遵循最新 iOS 与项目需求。Theme 设置控制 Options 页面自身外观。

Browser 侧为每次调用绑定实际 BrowserContext、普通或私密作用域和调用页面身份。渲染端提交的数据经过原生解析与版本校验后进入现有服务。读取结果包含可用能力、已提交版本、草稿状态和运行状态，避免将编辑值显示为已生效连接。

### 配置编辑和发布

配置页分别维护草稿、已持久化版本、已激活版本和当前限制屏障。Apply changes 使用父操作 ID 跟踪一次用户操作，子操作的 ID 由父 ID 和阶段确定。预期版本与同值操作 ID 沿用现有幂等、冲突和归属校验。同一个 ID 携带不同内容得到冲突结果。

复用 `AccessRuleStore`、异步存储、`AccessSiteIntentStore`、`AccessSiteProxySession` 和 `AccessServiceCoordinator`，按操作语义发布。

| 变化 | 发布路径 | 失败和取消 |
| --- | --- | --- |
| BLOCK / REJECT 及收紧限制 | 立即安装本地限制屏障，按既有合同终止在途请求并确认，然后持久化 | 不等待代理、账号或额度。保存失败时保留当前进程的限制屏障并显示实际保存状态 |
| 关闭代理 / 进入 DIRECT | 撤回本操作拥有的防护例外，按本地版本发布新请求路径 | 可在离线时执行。保留其他操作和更新版本的限制 |
| 新增 PROXY / ALLOW / 依赖新代理的放宽 | 校验完整引用图，准备代理，经安装与执行点 ACK 后持久化并完成激活 | 准备失败维持此前安全策略。放宽前要求的屏障持续生效 |

一个 Apply 同时包含上述变化时，先独立执行有效的限制操作和本地关闭操作，再处理需要代理准备的变化。Profile 图和依赖它的规则在各自发布事务中保持一致。结果逐项报告已阻断、已保存、等待准备、未提交或已保存但暂不可用。代理准备失败不能撤销已经生效的 BLOCK，也不能让其他本地关闭操作等待账号服务。

BLOCK / ALLOW 进入既有本地动作通路。普通 DIRECT / PROXY mutation 使用 `AccessServiceCoordinator`。Options 的父操作协调两类通路，并持久化可查询的子操作结果。

发布状态区分 `PREPARED`、`INSTALLED_ACKED`、`DURABLE` 和 `FINALIZED`。本地拒绝和关闭路径跳过网络准备。快照返回 `committedRevision`、`activeRevision`、运行时 generation、逐项状态和 `dispatchPermitted`。持久化阶段遇到身份或 NetworkContext 变化时，保留 `kCommittedUnavailable` 结果，展示新的已保存版本及不可用状态，屏障维持阻塞，随后按新上下文重新准备和激活。

超时后先按原操作 ID 查询操作状态，再确定重试。持久化前仅撤销仍归该操作拥有的临时变化，不能覆盖较新的 BLOCK。持久化后取消只取消后续恢复尝试，恢复旧意图需要新的显式编辑事务。Discard changes 丢弃当前草稿并读取最新已保存快照及限制屏障，不能回滚已经持久化的变化。重启时先恢复存储和未决发布状态，无法确认的请求保持恢复屏障。

状态查询遵循现有 journal 的保留与容量限制。记录已过期或无法找到时，读取当前已提交版本及受影响行的版本，核对操作内容后返回已生效、冲突或结果不确定。结果不确定期间保留屏障和明确反馈，不自动生成新 ID 重放业务请求。

产品规则库保留现有 `<Profile>/access.db` 及 singleton 渠道身份合同。高级配置使用 `<Profile>/AccessOptions/<compiled-channel>/options.db`，凭据句柄按安装身份、渠道、实际 Profile 和用途分开命名。Options 不向其他渠道的库写入配置或凭据。

同渠道旧 Options 数据采用带版本的临时库事务迁移，校验完成并持久化迁移状态后切换，原库保留为恢复来源。启动过程中保持恢复屏障。中断后根据持久化迁移记录继续或恢复原库。

物理 Profile 中现有产品规则库的渠道与当前渠道不一致时，保留 `AccessRuleStore::Open()` 的 `kConflict`。不重写原 singleton，不以空库替换，也不将已有代理意图当作无规则。UI 呈现渠道冲突和原有恢复阻塞状态。M2 验收该拒绝路径，跨渠道配置转移由 M8 的显式导入处理，凭据必须在目标渠道重新绑定。私密 Options 配置只存内存，随实际私密 Profile 结束清除。

### Profile 和路由

首先逐字段清点固定参考版本的 Options 模型，建立字段、验证规则、原生表示、渠道能力和验收用例的对应表。清点范围包含内置 Direct / System、固定代理、PAC、切换 Profile、规则列表、间接引用及参考项目实际提供的配置项。

配置分为项目 Access 策略和内部 Chromium 基础代理配置两层。先执行管理和安全约束，再按现有本站规则、Profile 规则及默认策略计算 Access 结果。内部 Profile 选择产生基础代理配置，供 Access 的 `preserve_native` 路径消费。

| Access 结果 | 内部基础配置 | 业务请求的实际处理 |
| --- | --- | --- |
| REJECT | 任意 | 原生本地终止业务请求 |
| PROXY | 任意 | 使用现有已注册的 numeric-loopback endpoint 和专属路由上下文 |
| DIRECT / preserve_native | Direct Profile | Chromium 基础配置为显式 DIRECT，经过正常防护发送 |
| DIRECT / preserve_native | System Profile | 使用经过原有管理优先级处理的系统代理配置 |
| DIRECT / preserve_native | Fixed Profile | Chromium 原生代理配置表示远端 HTTP / HTTPS / SOCKS 等受支持代理 |
| DIRECT / preserve_native | PAC / switch / rule-list Profile | Chromium PAC 与基础代理解析得到本次 Native ProxyInfo |

`ApplyRoutePlanToProxyInfo()` 的项目 PROXY 合同保持单个已注册回环端点。远端代理和 PAC 结果通过内部基础配置适配器进入 Chromium 原有代理解析，不伪装成 Access 注册节点。Options 显示实际命中的 Access 策略及基础 Profile，区分 System 继承、显式 Direct 和项目 DIRECT。

基础配置适配器接在 Profile 的 `ProxyConfigMonitor` / `ProxyConfigService` 创建与更新路径，持有受信内部能力和已提交的 Profile 选择。它保留原生管理优先级与不可控状态。受限渠道返回原有配置服务。内部选择持久化在 Options 库，避免写入跨渠道沿用的通用代理 Pref 后在 Beta 意外激活。

PAC 的 `PROXY P; DIRECT` 等列表只在项目结果为 `preserve_native` 时按 Chromium 原有 PAC、mandatory 与失败处理语义执行。项目要求 PROXY 时继续使用已确认回环路径，故障保持等待或失败。REJECT 不向业务目标发送请求。auto switch 及其条件决定基础 Profile，不能覆盖前述 Access 策略顺序。

每个实际 Profile 只有一个已提交基础 Profile 选择，按预期版本竞争提交。同一个 Profile 的 NetworkContext 通过同一配置 generation 更新。选择、PAC 更新、系统代理变化、凭据变化和身份撤销都会使相应 generation 失效，旧准备、旧 ACK 与旧连接不能证明新配置可用。普通和私密上下文各自持有配置、代理认证缓存与凭据引用。

M6 先完成基础配置适配原型。Network Service 安装基础配置时确认其版本、NetworkContext 和 Profile 归属，Browser 在收到对应确认后发布 active revision。未收到确认的相关请求由恢复 / 发布屏障等待。请求解析使用匹配的基础配置 generation，旧回执、服务重启及已撤销凭据的连接均不能越过该屏障。未启用内部 Options 的旧调用路径继续使用原有配置和协议默认值。

规则图验证缺失引用、循环、冲突、默认去向和删除引用。手动代理凭据使用独立用途的受信原生句柄，账号服务凭据保持其原有归属。原标签重试继续绑定失败 URL、方法与导航身份。POST/PATCH 等已发送业务按原重放合同处理。防护、CORS、缓存和连接隔离沿用现有实现约束。

M6/M7 的受控出口测试覆盖上述全部组合、PAC mandatory / 非 mandatory 失败、显式 DIRECT fallback、系统代理 A→B、两个同时提交的 Profile 选择、托管配置拒绝、凭据代次变化及 Access PROXY 失败。检查实际出口、首个网络发送和连接复用结果。

### 账号与用量

参考最新 iOS 的 `BrowserSettings`、`AccessUsagePage`、`AccessSubscriptionUsageView`、`AccessAccountUsageView` 和两个 Session，提供统一入口。

页面首先按 iOS 的来源选择合同决定数据源。

| 上下文与来源状态 | 页面结果 | 连接准入 |
| --- | --- | --- |
| 私密窗口 | 提示在普通窗口查询 | 不读取普通账户的用量或凭据 |
| 普通窗口，subscription.isSelected 为真，配置无效或请求失败 | 共享测试来源不可用，已有计数标陈旧 | 不转用 account 来源或静态节点 |
| 普通窗口，共享测试来源计数有效但 allowance 不允许连接 | 展示有效计数及停用、耗尽或到期状态 | 拒绝新连接，撤销失效连接能力 |
| 普通窗口，共享计数及 allowance 有效，但节点发现失败 | 保留有效计数，连接显示暂不可用 | 清空旧节点列表并拒绝静态节点回退 |
| 普通窗口，共享计数、allowance 和当前节点列表均有效 | 展示共享测试账户、自动连接数量和用量 | 仅使用当前成功 generation 中属于该用户的节点 |
| 普通窗口，subscription.isSelected 为假 | 进入 AccessAccountSession 的未关联、查询中、有效、陈旧或不可用状态 | 用量观察通过独立的账号节点授权合同使用，余额显示不直接授予连接 |

两个服务同时配置时仍按 `isSelected` 选择，不能拼接其计数或在错误时换源。切换来源、账号或身份使旧请求和节点 generation 失效。页面覆盖已用、总量、剩余、上传、下载、到期、上次查询及刷新。整数计数在原生与 WebUI 间使用经校验的十进制表示，覆盖超过 JavaScript 安全整数范围的值。

刷新复用账户刷新协调逻辑，覆盖重复刷新、可见性、后台返回、取消、登出和旧响应。失败时保留带陈旧标识的最后有效结果。账号凭据和手动代理凭据各自使用既有安全存储和身份代次。

### 日志、导入导出与鸣谢

日志对齐参考项目的错误日志保存和诊断能力。Xray 文本继续经过 `AccessCoreLog::Add()` 的既有语法识别和脱敏。Access 规则命中、准备、ACK、失败资源、重试及 Options 错误通过独立的类型化事件 API 记录。

事件格式为 `AccessDiagnosticEvent` v1，包含时间、级别、类别、受信渠道和作用域、事件枚举、操作 ID、请求关联 ID、已提交和已激活版本、上下文 generation、结果与原因枚举。目标字段仅接收经验证的 host / scheme / port。字段有类型和长度白名单，未知字段、版本和自由错误载荷不能直接进入日志。凭据、订阅内容、Cookie、请求头、正文、URL 路径及 query / fragment 不进入该事件格式。

类型化事件使用独立的 `regular.events` / `private.events` 流，复用安全文件访问和清除代次机制，避免与 Xray 的 `regular.log` / `private.log` 相互覆盖。每个流最多 128 条且最多 64 KiB，单条上限 4096 字节，达到任一限额则按顺序淘汰最旧记录。追加、磁盘恢复、查看与导出均执行版本、字段和受保护值校验。一次导出选择一个渠道和普通或私密范围，包含该范围的两个已校验流、格式、版本和截断信息，上限为 132 KiB，其中元数据最多 4 KiB。

私密日志沿用当前已披露的保留行为。历史挂在 OriginalProfile，启用保留时 `private.log` 可以跨私密窗口关闭继续保存在磁盘，类型化私密历史使用同一保留选择。此行为与私密 Options 配置的内存生命周期分别处理。

Options 明示当前普通 / 私密范围、保留状态及现有“退出后仍保留最近 128 条，可能包含私密目标地址”的提示。分享沿用已有预览和确认，确认绑定渠道、作用域、view version、generation、clear epoch 和快照摘要。快照改变时旧确认失效，取消不生成文件。Clear 和 none 清除所选范围的两类历史，并以清除代次阻止旧加载和写入恢复已清数据。存储失败显示实际错误，不能宣称磁盘历史已经删除。

验收覆盖私密窗口关闭后重开、普通与私密选择、另一渠道、clear / none、取消、预览后追加或清除、写入失败和重启。分别核对内容保真、字段脱敏和真实保留状态。

导入先解析为草稿并展示校验结果，再经同一 Apply 事务生效。导出记录格式与版本，按实际作用域读取已提交配置。取消、损坏文件、未知字段、重复名称、循环引用、失效凭据引用、跨渠道配置和保存失败均保留可恢复结果。Reset options 使用相同版本控制与发布路径，并按项目原有确认规范处理。
