**3. R2 页面样本的适用边界**

公开页面输出中仅登记非秘密字段：`type=ws`、`security=tls`、`allowInsecure=1`。
这些字段反映页面生成内容，不能证明服务端真实配置、订阅可用性、可达出口或账户控制权。

- `allowInsecure=1` 与规范第 7 节“不得关闭验证”的合同冲突，该样本只能先作为导入拒绝的负例。
- 不将样本原样加入有效节点池，也不靠忽略该字段使其通过配置校验。
- 正向 WS+TLS 兼容测试需要合法证书、保持证书验证的配置，并在授权环境验证真实链路。
- 管理 UI 中的多个 HOST 不证明多个账号、独立 VPS、独立故障域或额外容量。

负例的导入拒绝测试本轮仍为 `NOT_RUN`；页面观察不能代替解析器或原生接口执行证据。

| 顺序 | 操作与产出 | 对应合同及边界 |

小流量功能验证不授权无上限测速。吞吐压测、并发规模、字节预算和超限停止条件须按既有容量合同确定；未知额度不能填成无限。

**7. 模型分工与交付交接**

更新日期：2026-09-14。以下为用户最新指定的本项目、本任务执行约定，替代此前“架构 Astra 极高、实现 Astra 中”的分工；不代表已修改全局设置或 API 默认值。此前资源观察和验证记录仍对应其原记录日期。

| 阶段 | 配置 | 必须产出 |
|---|---|---|
| 架构设计 | Astra · 高（`gpt-6-astra` / `high`） | 范围、模块边界、接口、不变量、验收用例、回滚办法 |
| 实现 | Sol · 极高（`gpt-5.6-sol` / `xhigh`） | 代码、相关测试、实际执行结果；发现设计问题及时反馈 |
| 独立 Review | Astra · 高（`gpt-6-astra` / `high`），新上下文 | 对照原始需求检查代码，也可质疑架构；问题注明具体位置、触发条件和影响 |
| 修复与复审 | Sol · 极高修复，Astra · 高复审 | 关闭阻塞问题，验证相关回归，更新问题处置与验证证据 |
| CI → 合并 | 绑定最终 head SHA | 必需门槛通过、审查覆盖最终代码，再合并并检查 main |

需要某档位而工具不可用时，明确报告受影响的任务和可用选项，不静默更换模型或推理档位。模型标识按执行环境核验，不能将产品版本号与推理档位混为一谈。

交接按“架构设计 → 实现 → 独立 Review → 修复与复审 → CI → 合并 → main 检查”推进：

1. 设计交接记录原始需求、规范版本、实际 base/head、目标 P 单元、范围、模块边界、接口、不变量、验收用例、回滚办法及仍缺失的参数。设计假设与已验证事实分开。
2. 实现按授权任务交付可审查差异、完整接线、相关测试、实际执行命令及结果。发现设计问题时提交触发条件、影响与建议；不自行降低冻结验收要求。明确的只读、设计阶段或暂停边界继续有效。
3. 独立 Review 使用新的上下文；以子代理执行时使用 `fork_turns="none"`。提供原始需求、必要的适用指令、规范路径、base/head、完整差异入口和测试证据；不以实现者总结替代源码，不复制其推理历史。Reviewer 可以质疑架构，发现需写明文件/行号、触发条件、影响及严重程度。
4. Sol 修复阻塞问题并运行受影响回归；Astra 核对修复差异、影响范围与更新后的证据。复审可保留同一独立 reviewer 的问题上下文，不能只凭实现者声明关闭问题。
5. CI 与审查结果绑定具体 head SHA。新增提交、rebase 或修复后更新最终 head，并补足受影响的审查与必需检查；旧头、排队、跳过或取消的结果不能替代最终代码的成功证据。检查通过且审查覆盖最终代码后，在已授权交付范围内合并。
6. 合并后记录合并结果及实际 main SHA，检查必需的 main 门槛；失败则继续定位并按项目流程修复或回滚，不能仅以 PR 已合并宣称交付成功。保留规范第 14 节的运行清单、子项结果和脱敏证据。

此流程约定不自行启动当前尚未授权的产品实现或合并，不修改冻结的产品行为。文档审查只证明对应文档差异，不授予产品运行或 G0–G3 通过结论。
