# Aegis V1.0 出站协议与 DPI 评估

日期：2026-09-13；对应冻结修订 4。评估对象是协议选型，不是某个已部署域名。结论属于公开资料核对与工程判断；未运行 Xray、未测试真实网络或部署配置。

**结论：保留 VLESS + RAW(TCP) + REALITY + XTLS Vision 作为主路径是合理的；VLESS + WS + TLS 适合作为兼容路径，不能视为同等抗 DPI 的备用。当前不能给实际部署标注“抗 DPI 已通过”。**

| 选型 | 本项目判断 | 使用边界 |
|---|---|---|
| VLESS + RAW + REALITY + Vision | 适合作为自有 VPS 的主候选，有降低协议特征和应对未认证探测的设计依据 | 固定内核、正确配置并在目标网络验证后使用；不能保证避免 IP/SNI 封锁或长期流量分类 |
| VLESS + WS + TLS | 保留已有兼容需求；不作为抗识别能力相同的替代品 | 单独登记兼容类别和测试结果，不在主协议失败时未经策略授权自动切入 |
| XHTTP 路径 | 值得在需要新兼容方案时单独做 P0 比较 | 尚未纳入 V1.0 必需交付；不因上游推荐就声称当前服务端、计量和故障恢复已兼容 |

REALITY 借用目标站的 TLS 外观，未认证连接会回落到目标；这为降低服务端特征和应对探测提供机制基础。其目标必须与部署相容，上游最低建议包括 TLS 1.3、H2 和非纯重定向域名。这里据机制判断它适合作为主候选，并非引用了本项目成功穿透某个 DPI 的实测。[REALITY 官方项目](https://github.com/XTLS/REALITY)

uTLS 只模仿 ClientHello，并不让整个连接行为等同于真实 Chrome。因此 `fingerprint=chrome`、端口 443 或成功打开网页，都不能单独证明抗识别。目标 IP、可见的握手字段、连接持续时间和流量形态仍应进入测试范围；这部分是本项目的威胁模型，而非声称已发现当前部署漏洞。[Xray TLS 指纹说明](https://xtls.github.io/en/config/transports/tls.html)

WS 的弱点有明确上游依据：官方文档提示 `http/1.1` ALPN 等显著特征，并建议考虑 XHTTP。TLS 仍提供链路保护，但“加密”不等于“无法识别代理用途”。据此，本方案保留 WS+TLS 的兼容定位，不给它与主路径相同的抗 DPI 承诺，也不把经过 CDN 或换域名当作证明。[Xray WebSocket 说明](https://xtls.github.io/en/config/transports/websocket.html)

2023 年的测量研究展示了基于流量特征、无需解密内容的封锁机制；研究对象、网络和时间均有限。它支持“不能从加密推导不可识别”这一判断，不能用来证明 2026 年某个 REALITY 或 WS 配置必然成功或失败。[USENIX Security 2023 原始研究](https://gfw.report/publications/usenixsecurity23/en/)

还有一项与本产品直接相关的集成风险：上游 VLESS 文档说明某些 Linux splice 路径会延后统计更新。本项目要求秒级用量、有限字节租约和耗尽截断，不能依赖连接结束后的累计值执行在途额度。保留 Vision 协议，先验证可实时计量和限额的转发路径；没有证据时不启用对应快路径，具体选择/适配方式必须在固定内核上实现，不能臆造配置开关。此风险可能增加 P0/P3c 的工作量，当前没有证据量化增加天数。[VLESS/Vision 与 splice](https://xtls.github.io/en/config/outbounds/vless.html)

实际验收至少包括下列独立结果；全部仍为 NOT_RUN，缺少环境参数时执行项记 BLOCKED：

| 检查 | 所需证据 |
|---|---|
| 配置与目标 | Xray/uTLS 版本、flow/transport/security、target/SNI、协商 TLS/ALPN、出口部署与签名配置 hash；秘密只记录引用 |
| 被动特征 | 在声明网络、时间窗口、设备和负载下记录握手/流量观测，与同环境正常 HTTPS 对照；报告误判和不确定性 |
| 未认证探测 | 仅对自有或获授权节点验证错误凭据、普通 TLS 请求等响应；同时检查回落滥用和资源预算，不对任意第三方扫描 |
| 连通性与封锁 | 分开记录握手失败、IP/SNI 受限、目标不可达、断流和恢复；多时段/目标网络结果，不从一次成功外推长期有效 |
| 协议切换 | 签名策略限定允许的出站类别；未获准 WS 不能进入主组备用；切换不直连、不重放业务 |
| 长连接计量 | 传输未结束时已持续更新权威字节；额度耗尽能截断，重启不丢账；覆盖实际使用的 Vision/splice 路径 |

REALITY 的目标回落本身也需要容量评估；上游特别提醒借用某些 CDN 目标可能形成可被滥用的转发入口，回落限速又可能带来额外特征。因此参数必须与真实 target 和资源预算一起验证，不能统一复制模板后宣布安全。[REALITY 配置与回落说明](https://xtls.github.io/en/config/transports/reality.html)

本次决策不改变两入站/两出站的功能验收范围。规范新增 A117/A118，并将兼容协议的授权、目标与网络证据纳入部署绑定；未来若比较 XHTTP，另立候选和实测结果后再修订协议范围。
