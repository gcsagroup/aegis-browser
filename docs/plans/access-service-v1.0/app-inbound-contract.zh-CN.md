## 路由范围与信任边界

Aegis 在本应用内决定哪些网页请求需要保护。受保护请求经本应用管理的回环监听、已授权的核心和选定上游到达目标。普通放行请求继续遵循其原有路由。iOS 按顶层导航为文档绑定 DataStore，macOS 按受信的请求归属逐请求、逐重定向选择路由。

本地两种入站都无用户名密码。SOCKS5 只选择无认证方法 0x00 并接受 TCP CONNECT。若客户端同时提供 0x00 和密码方法，仅选择 0x00。HTTP 入站在 iOS 使用 CONNECT，macOS 按 Chromium 的请求类型处理 HTTP forward 或 CONNECT。本地监听只绑定数值回环地址，控制面核验自己持有的监听实例、端口和代次。不同授权主体、私密作用域或互不相容的路由使用独立监听。兼容的引用可共享同一监听，释放一个引用须保留其余有效消费者。

三端应用内 SOCKS5 默认让操作系统为本代监听分配随机可用端口。监听器直接绑定端口 `0`，持有同一个 socket，从绑定结果读取实际端口再登记。内部测试需要一个固定 SOCKS5 端口时使用 `10806`。控制面拒绝在 `1080` 上启动或登记 SOCKS5，也拒绝实际端口为 `0` 的登记。自动分配返回禁用端口时，释放该候选，在原期限内重新分配或报告准备失败。指定的 `10806` 已被占用时报告冲突并保留原保护意图。上游分享链接中的端口仍按该节点配置解析。

回环限制了网络可达范围。能访问该 TCP 端口的本机客户端可以发起无认证连接。产品承诺是 Aegis 内部的归属正确、路由隔离与及时撤销。要求排除其他可达本机客户端的部署不能准入这两种本地无认证入站。上游 TLS、订阅、配额和节点认证仍按实际服务合同执行。本地 HTTP 不申请代理密码、不弹认证提示、不向源站传递代理认证头。远端显式配置的认证代理、账户专用下载通路分别验证。

DEV / 内部 Alpha 可在三端 Options 明确选择手动输入或扫码的 3X-UI 测试节点作为上游。该选择属于独立测试 Profile。本地监听的无认证仅适用于应用回环。托管订阅和账户各自核验身份、额度和撤销。托管来源故障时保持原授权结果。Beta / Release 的原生控制面拒绝手动测试节点激活。托管联调等待服务端同事交付。[渠道与交接条件](app-access-options-sdd.zh-CN.md)

## 登记与绑定

每次发布保存不可变的关联信息，包括 owner、普通或私密作用域、Profile 及其版本、上游授权代次、registration ID、监听实例代次、实际协议与地址。平台再记录 NetworkContext 或 DataStore 的实例身份。持久化的是用户意图和 Profile 引用，端口、探测结果和会话句柄随实例退役。

| 登记时的输入 | 发布结果 |
| --- | --- |
| 自动选择，SOCKS5 在本候选与平台已准入，本代监听由本应用持有，协议探测及受控上游检查通过 | 发布一个无认证 SOCKS5 端点 |
| 自动选择，SOCKS5 能力关闭、平台未准入，或准备期确认仅 SOCKS 协议不兼容 | 清理未发布的 SOCKS 候选并确认资源释放。确认后，只有无认证 HTTP 在本候选、平台和渠道已独立准入，且在原时限内通过同一授权范围的监听所有权、协议探测及受控上游检查，才发布一个 HTTP 端点并记录原因。任一条件不满足时阻断受保护请求 |
| 内部设置明确锁定某种协议 | 只验证指定协议，失败时给出可读状态。O3 可据此独立验收 HTTP |
| owner 或代次冲突、端口所有权不明、授权失效、额度耗尽、上游健康或 TLS 失败、结果含糊、两种协议均未准入 | 在原操作期限内等待或明确失败。禁止借另一运输延续已失效授权 |
| 已发布端点失效、出现意外本地 407、停止或撤销 | 使本代不可用，拦住受保护请求并终止所属流。恢复必须从一个新登记开始 |

协议探测使用受控目标，在首个业务字节前结束。单次业务请求只绑定一个端点。Chromium 使用单一 proxy chain，WebKit 安装单项配置并关闭直连 failover。记录实际运输、选用原因、作用域和代次，不记录账户秘密。运行时故障禁止改走另一协议、DIRECT 或重放 POST/PATCH。用户明确关闭保护后的后续导航按其新意图处理。

## 撤销、迁移和回滚

先封住撤销范围内的新派发。监听实例整体退役时停止接收新流量，原 socket 继续绑定地址。随后取消撤销范围内已接受的连接、上游桥、待处理探测和重试。迟到的成功回调按 owner、操作和代次丢弃。只有相关旧文档或网络上下文均确认无法再向旧地址派发，且该代的流已终止，才关闭 socket、释放并允许复用端口。端口占用、退役超时或确认缺失时保留失败屏障，未确认退役的监听继续持有地址。应用或网络进程重启后从持久策略重新取得上游授权、启动监听并登记，新端点就绪前强制保护保持关闭派发。

旧版本的本地 HTTP 凭据、仅有 host/port 的记录和未知版本均不得解释成有效的新式登记。升级时保留持久路由意图，重新建立监听和绑定。回滚时按回退版本能理解的合同重新登记；失效的旧代次不得复活。关闭 SOCKS 准入只影响下一次登记，切换现有绑定须走完整退役流程。

恢复旧配置时，原自动模式重新分配端口。原配置若显式指定了已禁用的 SOCKS5 入站端口，保留路由意图并提示修正。旧地址不得激活，也不能据此改投 HTTP 或直接派发。

## 冻结修订与验收归属

| 要修订的条目 | 下一版的关闭条件 |
| --- | --- |
| §1 浏览器入站总览 | 先打通无认证 HTTP，SOCKS5 单独验证无认证转发、隔离与撤销。两种入站各自通过后才可宣称完整支持 |
| §7、P3、A78-HTTP | 应用内无认证回环 HTTP。受信登记后真实转发，零本地凭据或认证提示，未知/过期登记和非回环地址拒绝，互异 owner 并发隔离，撤销后旧流终止 |
| §7、P3、A78-SOCKS | 应用内无认证 SOCKS5。仅密码方法、BIND、UDP ASSOCIATE 拒绝。另验登记、并发、撤销与真实转发；listener 的握手计数不构成出口回执 |
| P0、G0 | 将 P0 的 HTTP/SOCKS 本地认证原型改为两种无认证入站的独立运行验证，分别覆盖真实转发、登记隔离与撤销。G0 仍须固定基线上的实际构建和修订后 P0 的运行证据，其他 P0/G0 条件继续独立验收 |
| W1c、G1 | W1c 的本地凭据拒绝矩阵改为上述两组登记隔离和撤销矩阵，保留完整的连接复用键与生命周期检查。G1 的 HTTP→REALITY 和两个普通 Profile 保留。W1 请求级隔离在 macOS 单独验证 |
| A89、iOS O3/O6 | 入站、上游认证和实际出站分别列证据。A89 的两入站 × 两出站按组合记录。iOS O3 固定 HTTP，O6 的 HTTP 和适用上游项独立进行，只有 SOCKS 子行以该平台准入为前提 |

正式修订沿用 A78 主编号和历史结果，同步规范、架构、开发计划、W1c 交接、验收台账和受信冻结清单。版本、历史摘要及对上版的差异应可审阅。在新修订和平台验收完成前，默认开关保持未准入。[冻结规范](spec.zh-CN.md) · [W1c 合同](FEATURE-HANDOFF-W1b-W1c-preparation.zh-CN.md) · [验收台账](acceptance-tracker.zh-CN.md) · [冻结校验](../../../scripts/ci/check-access-freeze.mjs)

每个平台的同一候选须提供三类收件证据。受保护请求带本次标记到达指定出口；显式选原连接的独立对照确实收件；强制路由失效后，原连接出口新增收件为零。记录源码、构建或补丁树、系统、实际协议、代次、标记、请求范围与失败原因。协议夹具、模拟器、真实浏览器或设备、发布分别记账。
