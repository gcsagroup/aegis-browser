# iOS 精确主机存储 — 剩余产品路径 SDD

日期：2026-11-10。状态：规格，不是实现完成或允许合并的声明。  
基线：上游 PR [#97](https://github.com/gcsagroup/aegis-browser/pull/97) 头 `a4f8ad139e1ace782eba629183ec6057c0407ed8`，加上本地工作树里尚未进入该 PR 头的 iOS 路由改动。  
范围：只写 iOS 上还没接通的产品路径。页面改走专用存储，和真实网站经 VLESS 打开，分成两次验收。

## 1. 已固定、本规格不再改的行为

- 存储键是 `HostStoreKey = 浏览作用域 + 规范化精确 host`。
- 普通作用域由同一普通配置下的所有窗口共享。私密作用域由同一次私密会话共享，用 `privateSessionID` 区分。
- `example.com` 与 `www.example.com` 不是同一键。普通与私密、两次私密会话彼此隔离。
- 每个标签保留创建时的 `originalStore`。回到原连接必须回到这份对象，不能再调用 `nonPersistent()`。
- 同一页面的图片、脚本和接口跟随该页面的存储。专用存储不设置 `matchDomains`，并设置 `allowFailover = false`。
- 其它主机的页面不使用这份存储，继续走系统原连接。
- 已经绑定专用存储后，端口失效仍保持该存储和代理配置，请求失败，不切回原连接。
- 只有用户关闭代理，或私密会话结束，才解除绑定并淘汰专用存储。
- 跨主机主导航一律重建 WebView。前进后退历史、Cookie、DOM 和表单不迁移。
- GET/HEAD 的主导航网络失败最多自动恢复一次。POST/PATCH 不改成 GET，也不自动重发。
- 私密会话在关闭最后一个私密标签、明确结束私密会话或关闭所属窗口时结束。切换普通模式、切换标签和进入后台不算结束。

这些规则已经有纯逻辑测试，以及用可控本机 HTTP 代理记录 WebKit 请求的测试。测试通过只证明路由和存储，不证明真实网站经 VLESS 打开。

## 2. 本规格要补上的缺口

用户仍不能完成这条路径：

> 网站无法访问（默认原连接）→ 点击「通过代理重试」→ 本应用管理的代理入口就绪 → 只重载点击按钮的原标签上的原失败网址。

当前应用里的开关仍使用失败关闭编排。没有任何产品代码把代理入口标成就绪，`retryReadyTabs()` 没有被调用。失败页没有「通过代理重试」。没有 iOS 内嵌内核，也没有把 VLESS 接到专用存储的入口上。

## 3. 规格条目

### R1. 失败页入口

主导航因网络失败无法打开时，在该标签上提供「通过代理重试」。不宣称已经检测出网络封锁。HTTP 错误状态、证书错误、安全策略拦截和用户取消不出现这个入口。

### R2. 入口身份

「就绪」必须来自本应用管理的代理入口，并带有入口身份和单调版本。端口号非零或 TCP 能连上不算就绪。旧版本回调不能覆盖新版本，也不能在用户关闭代理后重新启用存储。入口就绪不写成目标网页已经打开。

### R3. 重试绑定

失败时记下恢复票据：`tabID`、`scopeID`、`navigationID`、精确 host、失败 URL、实际方法、开关版本、`retryConsumed`。

入口已经就绪时，GET/HEAD 仍只自动恢复一次。发送前先把额度标成已使用。这次自动恢复再失败，不能再自动生成额度。

「通过代理重试」是另一次用户操作。入口还没就绪时，它启动同一次准备；准备成功后只重载这个标签。自动额度用完以后，用户再点一次，仍可以再发一次，不改回原连接。

新导航、手动刷新或停止、关闭标签、关闭代理、结束私密会话都会作废尚未发出的票据。新导航即使仍是同一个 host，也作废旧票据。原有的「重试」只在当前存储上重新加载，不启动代理。

### R4. 重载范围

只重载点击按钮的那个标签上的失败 URL。同一作用域里已经使用该主机专用存储的其它标签不自动重载。其它主机的标签不变。

HEAD 必须仍以 HEAD 发送，不能经 `load(URL)` 改成 GET。POST 和 PATCH 只说明需要重新提交。

### R5. 两种不可用

界面必须能区分：

- 尚未接入：意图可以是开启，当前页面仍使用原连接。
- 已接入后失效：专用存储仍在，代理请求失败，没有切回原连接。

### R6. 准备时限

从点击到入口就绪或明确失败，单次准备总时限包含排队为 15 秒。超时保持可读失败，不自动无限重试，也不改走原连接。

### R7. 三次验收分开

- U：失败页按钮、15 秒准备、入口版本、专用存储和一次重载。证明页面改走了指定的本机 HTTP CONNECT 入口。
- K：同一个入口背后是进程内的固定内核，CONNECT 200 之后把字节交给 VLESS 出口，而不是停在一条空隧道上。证明这一次响应来自该出口。
- D：同一内核摘要、同一入口版本，在真机上重复 K 的这一次请求。

U 通过不能写成 K 或 D。应用里不放入只记录请求并返回固定页面的测试代理。节点配置不进仓库。

### R8. 一个入口，两处按钮

失败页按钮和「使用本服务代理」开关调用同一个入口发布器。发布器给出身份、版本、`127.0.0.1` 端口和状态。协调器只根据这个结果调用 `setEndpoint`，就绪后再调用 `retryReadyTabs()`。

全应用共用一个本机 HTTP CONNECT 入口。哪个标签走代理，仍由该标签的专用存储决定。不为每个 host 再起一个监听。

就绪必须同时满足：版本仍是当前这次准备、监听属于这次准备、内核仍在运行、CONNECT 之后的转发已经接上、没有超过 15 秒。只绑上端口、只收到 TCP，或会话控制器自己变成 ready，都不算就绪。

没有内核或节点时，发布器保持现在的失败关闭。意图可以是开启，页面留在原存储，并说明代理没有就绪。旧版本的回调不能把入口再标成就绪。

内核走进程内的固定摘要资产。不用子进程作为真机路径；模拟器能启动的外部程序不能代替这份资产。

准备超时、用户关闭该 host、或私密会话结束时，尚未绑定的页面留在原存储。已经绑定的页面保持专用存储，直到用户关闭代理或私密会话结束。

## 4. 场景

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| S1 | GET 主框架网络失败后点击重试，入口在 15 秒内就绪 | 只重载该标签的原 URL 一次，并改用该 host 的专用存储 |
| S2 | 同一次恢复再次网络失败 | 不再自动重试 |
| S3 | 恢复前用户打开了同一 host 的另一个路径 | 旧票据作废，不覆盖新路径 |
| S4 | POST 主框架网络失败 | 不自动重发，提示重新提交 |
| S5 | 入口尚未就绪时打开同一 host 的新标签 | 新标签留在自己的 `originalStore` |
| S6 | 已绑定后入口失效 | 保持专用存储和代理配置，后续请求失败，不出现原连接请求 |
| S7 | 用户关闭代理 | 相关标签回到各自 `originalStore`，专用存储被淘汰，旧票据不重发 |
| S8 | 15 秒内入口没有就绪 | 可读失败，页面仍使用原连接 |

## 5. 实现映射

- 失败文案已经在 `ActiveTabView` 里。网络失败时在现有「重试」旁边增加「通过代理重试」。资格沿用 `BrowserNavigationFailure.isRecoverableNetworkFailure`。
- 票据、额度和 `retryReadyTabs()` 仍在 `AccessHostStoreCoordinator`。按钮和开关都不直接改 `WKWebsiteDataStore`。
- `AccessHTTPInboundListener` 在 CONNECT 200 之后调用 `AccessHTTPRealityPath`，把隧道字节接到 `AccessRealityPathDialing`。现在这条隧道在 200 之后不再转发，所以即使有端口，网页也不会打开。
- `AccessXrayRuntime` 增加进程内启动。现有的进程控制器只留给测试。应用默认仍是 `AccessSiteProxyFailClosedOrchestrator`，直到进程内资产存在。
- 15 秒用可注入的时钟判断。单测不真的等待 15 秒。

## 6. 验收

U 的逻辑测试覆盖 S2、S3、S4、S7、S8。U 的 WebKit 测试用测试目标里的可控入口，覆盖 S1、S5、S6：重载走指定代理，另一个主机不走该代理，失效后没有原连接请求。这个入口不进应用包。

K 记录同一次候选的 CONNECT 主机、内核摘要和出口响应，不使用固定 HTML。没有节点时 K 记为未跑。D 用同一摘要在真机上重复这一次请求；没有真机时 D 记为未跑。

U 通过、K 或 D 未跑时，不更新 PR，也不写成产品闭环已经完成。

## 7. 非目标

不修改 macOS 或 Android。不换 WebKit。不做系统 VPN。不把子域并入父主机。不迁移 Cookie 和前进后退历史。不把测试代理的 200 响应写成目标网站已经打开。不用系统 `URLSession` 直连充当出口成功。
