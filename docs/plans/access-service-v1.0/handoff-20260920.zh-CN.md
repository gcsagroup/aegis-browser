## 本窗口唯一目标与完成条件

首个切片采用无冲突独立规则的配置，一个测试 Profile、一个测试账户、一个已授权受控节点：**开启网站代理 → 页面经指定出口成功加载 → 节点故障时不直连 → 恢复后重新成功访问 → 关闭规则后恢复当前原生行为**。关闭只影响网站开关拥有的协议组；更具体的独立 PROXY/REJECT 必须保留并正确显示限制，不能为满足“恢复原生”断言清除这些规则，其继续生效须另有回归。随后将真实计量与额度截断接入同一条产品链路。浏览器、代理与受控 origin 的关联证据缺一不可；fixture、ACK 或 UI 成功不替代真实请求。

修复结项必须同时证明原失败消失、安全约束保持、恢复后仍可使用。永久 fence/Busy 仅是安全中间状态；清库、测试专用 guard 或修改正例预期不算恢复。阶段性闭环不代表完整 W1/W2/W3、G0/G1 或 Alpha；两 Profile、认证、完整 BLOCK/生命周期/性能和最终分发条件仍保留。

## 调度、补强与停止规则

1. **当前 Q H → 实际释放并由 I 重新签收 → F 正向代理与恢复优先。** 不打断当前构建，不改运行输入，不清理 source/out/日志。历史 S 欠账保留；若不是 F 的技术前置，不自动先于 F。确有依赖时写出具体阻塞并单独分配，所有需要 S 证据的晋升仍等待。
2. 同链路只推进一个未经运行验证的行为改动。两轮针对同一正向场景的修复仍失败时，停止叠补丁，聚焦复核接口、状态归属和恢复边界，确定下一可证伪假设，再由原实现者继续。环境故障单独记录；不靠重跑掩盖不稳定。
3. 可靠性补强服务于闭环：先核已有用例，再补真实成功、故障无旁路、恢复/旧 ACK/取消、关闭规则及无关目标隔离；单元层验证状态边界，browser/service 层验证实际流量。完整 Profile/认证/入口矩阵继续保留，不把首个单 Profile 切片当全部覆盖。
4. 每次 owner 交接都核磁盘挂载/可写/容量、实际进程、锁、源码与输出身份。原 owner 安全释放和 I 的新签收均具备后才开始；不得并发 GN/Ninja 或重放。机器路径与 owner 身份只写私有记录。
5. 候选 VPS 线索只用于准备。真实 Xray 版本、binary/config、受控 origin、鉴权到账户映射、双向 writer/全部快路径、耐久/时钟合同与有限预算仍待绑定；现有两条线路属于同一 VPS，不是独立故障域。本计划不新增部署、凭据读取、付费流量或故障注入授权。WS+TLS 保留开发完成后回测 TODO。
6. 暂缓无关功能扩展、纯整理和同义交接。文档随代码/证据原位更新；自动化及晋升开关实时读取，不从历史恢复时间推断新的合并、晋升或发布权限。
