## 近期交付与估算口径

用户已确认当前唯一交付目标是个人内部试用：同一 macOS 产物、**一个普通 Profile、一个预置账户、一个已授权受控节点**，完成**开启网站代理 → 指定出口页面成功 → 节点故障不直连 → 恢复后成功 → 关闭后恢复当前原生行为**。关闭仅影响网站开关拥有的协议组，更具体的独立 PROXY/REJECT 保留；浏览器、代理与 origin 证据以关联 ID 对齐。完整真实计量、自动备用切换和 G1 验收留到后续，不作为本轮完成条件。

- **内部最小试用切片：10–20 有效人日，单主开发约 2–4 周。** 不包含完整真实计量、自动备用切换和 G1 验收；它是 W1 向 W3 的阶段性验证，不宣称完整 W3、G0 或 G1 已完成。
- **G1 受控 Alpha：从当前基线累计 40–70 有效人日。** 单人主导约 8–14 周；浏览器和服务端两条线有效并行约 5–9 周。累计量包含内部切片和首轮验证，不重复相加，也不自动授权创建并行任务。
- **下一阶段先投入 3–5 人日缩小不确定性。** 交付当前 155 Access 实际矩阵、F 完整 WIP 映射/第一失败、真实服务资源缺项和修订估算；即使结果为 BLOCKED 也保留真实结论，不承诺这几天内修完 W1。

分项工作量、资源假设、范围和完成条件统一见 [计划的估算章节](development-plan.zh-CN.md#内部试用与受控-alpha-的工作量估算2026-10-09)。这是低置信度工程估算，正常修复/验证已计入，外部等待及重大架构返工未计入；未合并工作尚未核验，不抵扣成已完成。G1 必需的双 Profile、认证、自动配置/保持/切换、真实计量和账户/物理限制继续保留；不以“最小”名义删掉安全门槛。
