## 已确定的技术调整

1. 保留主栈和冻结语义。请求级路由必须携带浏览器可信归属和版本，不能以 URL/NAK/活动页推断完整授权；单 endpoint host 配置仅为过渡，最终要支持同 partition 多组并存。
2. 先写固定 Chromium 的真实载体/API 清单并做原型，验证代理解析、连接池、HTTP/2、CONNECT/auth/retry cache 和重启隔离；不可只添加一个结构体后声称接线完成。
3. Vision 计量/截断/恢复作为独立早期 P0 实验，与 native 基线并行。固定拓扑决定 splice 是否适用；Stats API 不替代 durable 账本或数据面预算。
4. 工程验证先单执行节点、集中账本、有限测试账户，每 Profile 按需一个稳定 Xray；自动身份、真实切换、调试能力、完整公平限制等必须在 G1 前补齐。
5. 先证明真实浏览器纵向闭环，再扩展复杂入口；基础质量门、native、服务端、阶段验收和最终包分别记录。

## 可执行的接续检查

在所属 Aegis checkout 执行只读刷新；fetch 会更新 refs，应先按存储规则确认磁盘可写，不切换或重置共享工作树：

```bash
git status --short --branch
git fetch origin develop
git rev-parse HEAD origin/develop
git ls-remote origin refs/heads/develop
gh pr view 161 --repo quinn521/aegis-browser --json state,headRefOid,baseRefOid,isDraft,body,statusCheckRollup
gh pr view 162 --repo quinn521/aegis-browser --json state,headRefOid,baseRefOid,isDraft,body,statusCheckRollup
gh pr view 163 --repo quinn521/aegis-browser --json state,headRefOid,mergeCommit,body,statusCheckRollup
```

选隔离分支后先按 DEV 指南跑文档/代码对应的 full 门，native 由该候选的构建负责人运行。不要复制旧 candidate 路径、旧 filter 或旧 SHA 后直接宣布验收；实际命令、工具和原始结果必须随当次候选归档。
