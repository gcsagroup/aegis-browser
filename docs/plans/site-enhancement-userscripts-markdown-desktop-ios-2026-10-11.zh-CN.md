# 桌面与 iOS 网站增强和 Markdown 阅读开发计划

日期：2026-10-11。状态：用户于 2026-10-12 确认实施，开发中。

目标是在现有 Aegis 桌面浏览器和 iOS 浏览器中完成三项能力：按站点记忆的限制解除、用户脚本及 AI 编写、内置 Markdown 阅读器。完成标准是功能可操作、设置可恢复、权限范围正确，并有各平台独立的测试与操作证据。

本计划中的第一版和各阶段为用户已确认范围。2026-10-12 开始实施，开发完成后统一测试、实际操作、修复复测并提交分平台报告。

## 范围与关键选择

- 桌面以 macOS、Windows 为目标；macOS 使用现有固定 App 路径验收，Windows 单独构建和验证。Android 本轮不实施，在平台清单中如实记录。
- iOS 沿用现有 SwiftUI 与 WKWebView 工程，覆盖 iPhone、iPad，保持当前最低 iOS 18.4。遵循此前项目的模拟器验收范围，本轮以双模拟器为交付门槛；真机、TestFlight 和 App Store 发布另列后续门槛。
- `user.js` 指 `.user.js` 网页用户脚本。第一版兼容明确列出的常用能力，不承诺完整油猴兼容。
- 三项能力共用网站设置和现有模型配置。Markdown 阅读不依赖 AI，网站内置解除规则不依赖用户安装脚本。
- 不扩大为跨设备同步、完整编辑器、脚本商店、后台任务服务或另一套 AI 系统。

## 平台交付范围

| 能力 | 桌面 | iOS 和 iPadOS |
| --- | --- | --- |
| 网站操作恢复 | 恢复原生右键菜单，选取与复制单独控制 | 恢复可实现的长按、选取与复制；iPad 外接鼠标菜单单独检查 |
| 网站记忆 | 普通配置持久保存、重启恢复 | 普通模式持久保存，所有普通窗口一致 |
| 调试入口 | 现有 DevTools | 主动开启当前标签可检查，通过 Mac Safari Web Inspector 调试 |
| 反调试 | 浏览器能力加站点适配，保留用户断点 | 公开 WebKit API 与站点脚本适配；不承诺桌面内核级能力 |
| 用户脚本 | 导入、编辑、试运行、启停、导出与版本回退 | 同样的管理流程，使用原生移动界面和 WKUserScript |
| AI 编写 | 现有助手生成和修复脚本 | 复用 iOS 模型配置，生成适用于 iOS 能力集的脚本 |
| Markdown | 本地拖入、文件打开、在线文件、下载后打开 | Files 导入、分享至 Aegis、在线文件、下载后打开；iPad 拖放 |
| 阅读体验 | 目录、源码、搜索、主题、代码复制、打印及 PDF | 同样的基础阅读能力，适配触摸、动态字体和系统分享 |

iOS 的可检查开关只开放当前用户主动选择的网页，不开放内部设置、凭据页面或资料库。WebKit 的 `isInspectable` 支持从 Mac Safari 检查 WKWebView，但不等于在 iPhone 内嵌桌面 DevTools，也不能自动消除反调试逻辑。[WebKit 官方说明](https://webkit.org/blog/13936/enabling-the-inspection-of-web-content-in-apps/)

## 现有接入点与改动边界

桌面网站设置接入现有 Profile 配置、浏览器菜单及原生输入链路；脚本执行优先复用 Chromium 用户脚本基础设施，并在第一阶段核对当前构建的可用性。AI 复用现有模型路由，但脚本授权与普通 Agent 工具授权分开。

iOS 接入 [BrowserSession.swift](../../apps/ios/BrowserKit/BrowserSession.swift)、[BrowserPreferences.swift](../../apps/ios/BrowserKit/BrowserPreferences.swift) 和 [BrowserPreferenceViews.swift](../../apps/ios/AegisApp/BrowserPreferenceViews.swift)。现有 BrowserSession 已在文档开始时注入编辑状态检测，新脚本管理必须保留这类内置脚本，并与正在发展的 WebKit 保护功能协调注入顺序。

Markdown 使用两端共用的解析规则、样式资源和测试样本，宿主界面分别实现。阅读库复用既有保存入口，但不得将现有正文截断额度用于阅读器全文显示；保存超过资料库限额时明确提示或拒绝完整保存，不静默截断。

当前工作区存在多项未提交改动，iOS 构建号在本轮只读检查期间也发生变化。实施前必须重新确认活动写入者、基线和文件归属，不把已有未提交功能当作已合并基线，也不覆盖其他任务的改动。

3. 用最小验证程序检查桌面早期注入、原生右键恢复与调试会话共存；检查 iOS 文档开始注入、隔离内容世界、导航变更和可检查开关。
4. 确定本次实现支持的反调试模式、GM 接口和资源限额，建立真实网站复现记录和本地测试样本。

## 第二阶段 网站设置与操作恢复

依赖：第一阶段通过。

新增统一的“网站增强”入口，以及设置中的站点列表。提供恢复菜单、允许选取复制、反调试适配三个独立开关。解除规则默认关闭，用户主动加入后在下次访问自动应用；列表可暂停、删除和恢复默认。

- 默认按当前精确主机名匹配，限普通 HTTP/HTTPS 页面；界面显示适用协议和端口。包含子域名需显式选择，支持更具体规则覆盖。
- 正常窗口保存规则；私密窗口不自动继承用户脚本或持久化本次设置，临时规则随私密会话结束而清除。
- 桌面恢复原生上下文菜单，同时保持右键拖动手势、链接菜单和可编辑区域操作。
- iOS 在页面加载初期处理常见选取和长按限制；应用原生菜单提供恢复入口。对不可恢复的网页自定义控件给出明确状态。
- 设置更新对后续导航生效；需要重载的当前页显示提示，有未提交输入时不自动刷新。

验收：精确域名与子域名、重启、新窗口、多窗口并发、私密隔离、删除恢复、保存失败均有测试；实际操作确认普通网页、编辑器、PDF 和手势不回归。

## 第三阶段 用户脚本执行与管理

依赖：第二阶段网站范围与存储通过。

首批元数据支持 `@name`、`@namespace`、`@version`、`@description`、`@match`、`@exclude`、`@run-at`、`@grant` 和 `@noframes`。桌面与 iOS 共用匹配测试向量。执行时机覆盖文档开始、文档结束和空闲后执行；iOS 的空闲时机实现及差异必须记录，不能宣称与 Chromium 完全相同。

首批脚本能力为普通 DOM 操作、`GM_addStyle`、异步 `GM.getValue`、`GM.setValue`、`GM.deleteValue`、`GM_registerMenuCommand`。同步存储接口及未列明的兼容别名暂不承诺。普通模式的脚本值按脚本身份隔离并持久保存，私密模式只驻留内存。

管理器包含新建、粘贴或导入、编辑、试运行、启停、源码导出、运行错误与版本回退。新增和导入先保存为草稿；保存并启用后按授权网址自动运行。遇到不支持的必需权限或接口，停止启用并说明原因。

运行规则如下：

- 默认隔离执行。确需访问网页自身变量的脚本须显式选择页面环境；页面环境不暴露原生特权桥接。
- 默认只在匹配的顶层页面执行。子框架执行需要额外声明与逐框架匹配，处理重定向、空白框架和继承来源，不能以顶层授权覆盖所有子框架。
- 原生消息校验脚本身份、授权版本、标签、文档、来源及私密状态；页面伪造消息和导航后的旧消息均不能调用原生操作。
- 权限声明不等于对网页 DOM 或页面网络行为的完全隔离。安全扫描不能证明任意脚本无副作用，试运行前明确显示实际网站和可能影响。
- 停用后撤销后续注入与桥接；已改变的网页需刷新恢复。无限循环不能靠普通 JS 定时器保证停止，提供浏览器原生恢复入口，必要时重建当前标签内容。
- 禁止在内部设置、Markdown 阅读器控制页面等浏览器特权页面运行用户脚本。第一版不开放本地文件脚本注入。

Chromium 用户脚本支持不同执行环境和网址匹配；扩展更新后需恢复脚本注册，因此还必须测试应用升级、恢复注册失败和授权一致性。[Chromium 用户脚本文档](https://developer.chrome.com/docs/extensions/reference/api/userScripts)

iOS 使用 WKUserScript 的文档注入机制及 WKContentWorld；不把隔离世界当成 DOM 隔离。改动注入列表时统一重建保留的内置脚本与已授权用户脚本，避免误删表单状态检测、保护或阅读脚本。[WebKit WKUserScript 定义](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKUserScript.h)

验收：用同一组代表脚本在两端检查匹配、时序、样式、存储、菜单、重复注入、升级恢复与版本回退；通过伪造桥接、陈旧回调、跨脚本读值和错误脚本恢复测试。

## 第四阶段 反调试适配

依赖：第一阶段的能力验证与第三阶段的受控早期注入。

先覆盖重复 `debugger`、检测调试窗口后刷新或跳转、定时反复检测三类可复现场景。站点适配规则独立于用户脚本管理，随 App 版本提供，记录来源、适用域名、规则版本和最后验证时间。

首批目标为 CSDN 和 BOSS 直聘，桌面版网页与移动版网页分别取样。先记录原始失败，再启用规则做对照；只处理明确匹配的检测行为，不全局改写所有计时器、跳转或调试暂停。

桌面保留用户主动设置的断点。iOS 单独验证 Safari Web Inspector 连接和可适配的网页检测；做不到的模式明确标为平台限制。用户可按站点关闭规则，并在必要时重载恢复。

验收：已复现页面开启工具后不再发生目标刷新或跳转，且手动断点、登录、搜索、翻页和正常导航仍工作。网站改版、登录或验证码导致无法复现时记录未验证，不用本地样本通过替代真实网站验收，也不自动提交账号操作。

## 第五阶段 AI 生成与修复

依赖：第三阶段脚本权限、管理和运行通过。

桌面助手和 iOS 页面助手加入“为当前网站编写功能”。生成请求包含用户需求、当前平台支持的能力及必要的页面结构；按现有授权流程使用模型，不发送 Cookie、密码、验证码或全部浏览记录。

流程为需求输入、生成草稿、静态检查、效果与权限说明、用户点击试运行、结果检查、保存并启用。修复生成新版本，保留旧版；修改域名范围、权限或执行环境时必须重新授权。普通 Agent 不新增任意 JavaScript 执行工具。

AI 可根据语法错误和试运行反馈修复，但不能以模型自述判定成功。普通样式或 DOM 变更使用明确前后状态验证；涉及网络请求、表单或其他副作用的脚本不能伪装成无风险预览。第一版的自动修复仅处理语法和受控样本检查，不自动在真实登录页面反复执行。

验收：隐藏侧栏并加宽正文、添加回到顶部按钮、记忆显示偏好三项真实需求分别完成生成与持久启用；覆盖模型不可用、生成不支持的接口、恶意页面文字、选择器失效、导航后旧方案与权限扩大。真实模型链路和模拟模型测试分开记账。

## 第六阶段 Markdown 阅读器

依赖：第一阶段确定资源隔离方案、第二阶段网站偏好；AI 入口在第五阶段后接通。

解析组件采用 markdown-it，配合 DOMPurify 清理允许的 HTML，按需补充任务列表与代码高亮。依赖固定版本、保留许可证、随 App 打包，基本阅读可离线使用。[markdown-it](https://github.com/markdown-it/markdown-it)、[DOMPurify](https://github.com/cure53/DOMPurify)

第一版功能包括标题、列表、表格、引用、任务列表、图片、代码高亮与复制，目录和锚点、页内搜索、字体和宽度、深浅主题、源码切换、复制原文、打印及 PDF 输出。任务列表按文档内容只读展示，不自动改写原文件。

文件入口与边界如下：

- 桌面支持拖入和打开 `.md`、`.markdown`；iOS 接入 Files、分享入口和下载列表，iPad 支持拖放。导入为只读阅读，不修改系统默认文件关联。
- 在线优先识别 Markdown MIME；对于纯文本加 Markdown 后缀的候选提供预览入口并记住网站选择。只有后缀而实际返回 HTML 或二进制时不强制接管，已排版网页保持原样。
- 保留服务器要求下载的行为，完成后可在阅读器打开。受认证、重定向、POST 或一次性地址影响的文档避免另发一次请求读取；若平台不能取得原响应，使用已下载文件或明确告知需重新打开，不伪造原内容。
- 本地相对资源只在授权文件或目录范围内读取。iOS 单文件导入无法自动获得相邻文件时显示缺失提示，允许用户另选资源目录；不能默认扫描 Files。
- 渲染区与原生设置、凭据和文件权限隔离；禁止危险协议、脚本、表单动作及内嵌执行内容。远程文档不能访问本地资源；本地文档的远程图片按需加载。
- 正文渲染设置大小、嵌套和高亮工作量上限；对超限内容提供源码或下载退路，不静默截断正文。第一阶段确定并记录实际阈值。

阅读库保存、总结和翻译复用现有入口，但分别遵守保存容量、私密持久化及模型发送授权。完整 Markdown 原文与阅读库提取文本的区别必须显示。

验收：使用中文长文、表格、任务列表、相对图片、重复标题、代码、错误编码、恶意 HTML、离线和超限文档；检查两个平台的渲染、搜索、源码一致性、打印及 PDF 内容。iOS 额外检查竖横屏、键盘、动态字体、分享返回和文件授权失效。

集中验收的代表流程为：加入网站并解除限制 → 重启后自动应用 → 导入脚本 → AI 生成新脚本并试运行 → 保存与回退 → 打开本地和在线 Markdown → 切换源码 → 保存资料与导出 → 检查私密会话关闭后无新增持久记录。

发现回归先保留原始失败，修复后复测相关范围。脚本跑通、编译成功或模拟器通过均不替代其他平台的验收。跨域越权、私密泄漏、正常导航被误拦、无法停用恢复、旧资料不可读属于阻断项。

## 版本与回退

本轮包含多个功能，按大版本管理。只读检查时桌面为 Ver 3.0 (158)，iOS 为 Ver 4.0 且构建号持续变化；若实施时基线不变，拟分别升级为桌面 Ver 4.0 和 iOS Ver 5.0。实施前重新读取版本，避免与其他任务重号或回退；每次编译和打包递增各自构建号。

沿用同一 App 名称、路径、Bundle ID、签名身份和验收配置，保留旧候选及证据。新增存储带版本并支持原子写入，迁移前保留备份；回退读取失败不覆盖旧数据。

普通功能问题可关闭对应网站规则、停用脚本或关闭 Markdown 自动预览，再刷新页面恢复。代码回退只撤销本次变更，不动其他未提交工作。已经产生的外部请求或提交不能由版本回退撤销，界面不得承诺这类恢复。
