三件事

01

本地摘要是设计目标

桌面摘要的结构化脱敏与最终 POST 请求体已通过定向回归；完整 Chromium 出站审计和签名安装 App 证据仍未完成，Android 摘要当前不可用。

02

可解释拦截在验证中

当前源码的原生测试、Release 全量构建和代表性站点稳定性矩阵已通过；开关功能行为矩阵、安装 App 与启动压力验证仍待完成。

03

写进引擎，不是再装扩展

请求、参数、伪装域名和 Cookie 已集成到 Chromium，并随当前 build-tree App 完成构建；代表性站点行为与分发门禁仍待验收。它不是 Extension 交付物。

当前源码中的实验实现

跟踪器拦截
补丁序列包含 EasyList / EasyPrivacy 与部分第一方收集路径规则；最终行为待当前 App 回归。
链接与 Cookie
补丁序列包含去参和按名称分类清理 Cookie；保留登录态仍需代表性站点验证。
伪装与跳转
子资源 CNAME 与 bounce tracking 已有原生定向测试；代表性站点运行覆盖仍待完成。
指纹稳定化
Canvas、OffscreenCanvas、Audio、WebGL、WebGPU 反指纹已通过本地行为矩阵；目标是降低稳定识别，不是“无法指纹”，发布身份绑定仍待完成。
本机 AI 控制
桌面 HTTP、直接 target WebSocket、pipe 与所选 Target.* 路径已通过本地门禁；获授权的本机 agent 仍可读取 DOM，真实签名、Android 和完整协议覆盖尚未验收。

当前源码门通过后的下一验收

  1. 链接去参验收。 用代表性链接确认地址栏和请求中的参数行为。
  2. 钓鱼拦截验收。 用受控测试页核对阈值、原因和继续访问路径。
  3. 安装自动化边界验收。 在签名安装 App 上复核列表、直连 target WebSocket 与 Target.*，不能只看 build-tree 结果。

设计方向对比（非发布能力清单）

GCSA-aegis 常见做法
形态 Chromium fork，能力写在引擎 Chrome + 扩展，或套壳浏览器
页面 AI 使用本机启发式或用户配置的兼容 API；调用前确认目标 不少助手把整页送到云端
钓鱼 拦截并解释原因，可继续 只给警告，或完全交给云端扫描
跟踪 内核拦请求、清参数、揭 CNAME 扩展声明式规则，深度有限

现在不这样说

  • 已有可映射当前源码的 macOS build-tree App，但它不是 RC；没有通过身份、签名、打包和安装门的 App，也没有当前源码 APK，因此不提供试用分发包。
  • 指纹防护是降低跨站识别，不是让网站无法识别你。
  • 第一方收集按已知路径拦截，不宣称挡住所有服务端埋点。
  • 所选 CDP 场景仅在测试专用 mock Keychain 下通过；本机 agent 可读取获授权页面 DOM，签名安装、Android 和完整协议仍未验收。
  • AIM eligibility 与 policy FM/GCM 已有局部门禁，但不等于全部 Google/GCM 出站关闭；“无产品遥测”和“页面内容不出机”仍待完整审计。

当前状态

当前为本地开发 No-Go。已有当前源码的 macOS non-component build-tree App，本地 ad-hoc 严格结构校验已通过，但仍是 Chromium 身份、没有 TeamIdentifier 和分发包；出站审计、安装稳定性和 Android 验收完成后才能生成内部候选包。
