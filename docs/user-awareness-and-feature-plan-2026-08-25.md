# GCSA-aegis 功能改进与用户感知方案

- 版本：Implemented v0.3
- 日期：2026-08-25
- 状态：**U0–U3 已完成本地实施与验证**
- 产品边界：只做集成式 Chromium Browser，不恢复 Extension
- 实施边界：U4 未实施；只使用本地 Git，本地 ad-hoc 签名仅用于运行验证，不做正式签名、公证或发布
- 关联文档：[开发计划](./development-plan-2026-08-24.md)、[CPU 与论文优化](./audit/cpu-and-research-optimization-2026-08-25.md)、[论文映射](./research-map.md)

## 1. 结论与推荐

当前最缺的不是更多后台规则，而是浏览过程中看不到 Aegis 是否工作、做了什么、为什么做、出现兼容问题时如何恢复。

推荐先实施“**原生盾牌入口 + 当前站点保护面板 + 低打扰首次反馈 + 站点级恢复**”，再增加钓鱼解释、AI 上下文预览和有预算的论文研究能力。这样能直接利用已经存在的 `block / param / cookie / bounce / phish` 事件，不需要往网页注入脚本，也不需要先增加新的页面加载热路径。

不推荐用一个不透明的“隐私评分”或持续弹窗制造感知。评分容易把“本页未检测到事件”误写成“网站安全”，弹窗则会形成告警疲劳。产品应只陈述可验证事实，例如“本页阻止 12 项、清理 3 项、部分防护已暂停”。

## 2. 现状证据与问题

### 已有能力

- `chrome://aegis` 已集中提供 8 个模块开关、过滤列表状态、策略 worker、隐私摘要和 AI Control 状态。
- Browser service 已记录拦截请求、参数/Referer 清洗、Cookie 清理、bounce 清理和钓鱼阻断事件。
- 钓鱼拦截页已显示风险分、原因与权重，并提供“仅继续一次”。

### 用户感知低的直接原因

1. 正常浏览工具栏没有 Aegis 的固定入口、当前站点状态和动作计数。
2. 事件只显示在 `chrome://aegis` 长设置页的“本次会话”区域，用户必须主动输入内部地址并向下查找。
3. 当前事件是全 Profile 最近 40 条的文本列表，只对相邻完全重复项去重；没有 tab、文档或站点维度，也没有聚合计数。
4. 设置页每 2 秒拉取一次完整状态，即使用户只是停留在页面上；事件越多，列表越容易显得像调试日志而不是用户反馈。
5. 出现误拦或网站异常时，没有就地说明“哪个模块做了什么”，也没有明确的站点级临时恢复路径。

## 3. 目标、假设与完成标准

### 目标

- 用户在正常浏览时 5 秒内能找到 Aegis，并知道本页是否发生了保护动作。
- 用户点击一次即可理解“发生了什么、为什么、影响什么”，两次操作内可为当前站点临时恢复。
- 反馈不依赖网页 DOM 注入，不持续弹窗，不泄露完整 URL、查询参数、Cookie 值或页面内容。
- 新 UI 不引入持续轮询和每请求重绘，不破坏现有 CPU、稳定性和出站门禁。

### 关键假设

1. 桌面端优先落地；Android 使用相同状态合同，但入口按 Android 工具栏能力另行适配。
2. Aegis 只能说明自身执行的动作和模块状态，不能宣称当前网站“安全”或“无追踪”。
3. 默认只保留当前会话的有界聚合数据；无痕模式只保存在内存，不跨 Profile 汇总。
4. “临时允许并重新加载”是恢复方式；不承诺把已经删除的 Cookie 或已经取消的请求无损撤销。

### 完成标准

- 入口可发现、事件计数准确、tab/Profile 隔离、站点级恢复和状态降级都有自动与实际界面证据。
- 隐藏状态下无 WebUI 定时轮询；事件聚合和 UI 更新均有频率、内存上限。
- 代表站点稳定性、功能正负例、无痕、可访问性和 CPU 对照全部通过。

## 4. 推荐的用户感知方案

采用四级反馈，强度随风险递增：

```text
正常浏览
   │
   ├─ 无动作：工具栏盾牌保持安静，悬停显示“防护正常”
   │
   ├─ 有动作：盾牌显示本页聚合数量，点击展开站点保护面板
   │
   ├─ 首次认知：首次有效保护后只出现一次 4 秒教学气泡
   │
   └─ 高风险：钓鱼或敏感数据外发前才使用阻断页/确认页
```

### 4.1 工具栏 Aegis 盾牌

推荐增加浏览器原生固定盾牌按钮，不使用 Extension 图标，也不注入网页。

状态定义：

- **蓝色盾牌 + 数量**：本页已有可验证的保护动作；数量是聚合动作数，封顶显示 `99+`。
- **蓝色盾牌，无数量**：模块正常，但本页暂未发生可记录动作。
- **灰色盾牌 + 暂停标记**：Aegis 或当前站点保护已暂停。
- **琥珀色盾牌 + 感叹号**：规则过期、模块错误或部分能力降级。
- **红色只用于当前高风险阻断**：不作为普通拦截数量颜色。

颜色必须同时配合图标和文字，不能只靠颜色表达。文案使用“防护正常/部分降级/已暂停”，不使用“网站安全”。

### 4.2 当前站点保护面板

点击盾牌打开轻量原生气泡，首屏只显示当前 tab、当前文档：

```text
┌──────────────────────────────┐
│ Aegis 正在保护 example.com   │
│ 本页已处理 17 项              │
├──────────────────────────────┤
│ 阻止跟踪请求             12   │
│ 清理链接/Referer 参数      3   │
│ 清理跟踪 Cookie           2   │
├──────────────────────────────┤
│ 查看发生了什么                 │
│ 为此站临时暂停并重新加载       │
│ 打开完整设置                   │
└──────────────────────────────┘
```

展开“发生了什么”后只展示分组事实：类别、注册域、原因码、次数和最近时间。默认不展示完整路径、query、Cookie 值或页面正文；调试级原始信息继续留在受限诊断报告中，不直接进入用户历史。

### 4.3 首次有效保护反馈

- 新 Profile 第一次发生有效保护动作时，在盾牌旁显示一次 4 秒教学气泡：“Aegis 已处理本页的跟踪项，点击盾牌查看”。
- 每个 Profile 最多一次；不按网站重复出现，不使用系统通知，不播放声音，不循环动画。
- 用户点击或关闭后永久结束教学状态；之后只静默更新盾牌和面板。

### 4.4 高风险反馈

- 钓鱼继续使用全页阻断，但把技术分数降为次要信息，首要展示可理解线索：可疑域名片段、跨域表单、密码框、紧迫措辞等。
- “返回安全页面”保持主按钮，“仅继续一次”保持二级操作；不在本阶段增加永久白名单。
- 隐私摘要或未来 AI 操作在发送前显示“使用的上下文、脱敏结果、目的地和是否仅本机”，由用户主动确认本次任务。

## 5. 功能改进优先级

### P0：先做，直接改善感知与可恢复性

1. **当前站点保护面板**：展示本页分类计数、模块状态和分组原因。
2. **站点级临时暂停**：只对当前注册域生效，明确过期时间，并要求重新加载；面板可一键恢复默认。
3. **真实降级状态**：规则过期、worker 未就绪、模块错误必须显示琥珀状态，不能只看开关为开就报正常。
4. **事件合同重构**：从自由文本改为结构化事件，至少包含 tab/document、site、kind、reason、count、time 和可展示字段。
5. **事件聚合与限流**：按文档、站点、类别和原因在短窗口聚合，替代当前全局文本流水账。

### P1：第二阶段，增强理解与控制

1. **兼容性恢复助手**：网站异常时从面板选择“为此站暂停并重新加载”，恢复后提示是临时例外及其范围；不自动猜测并关闭全局功能。
2. **钓鱼解释升级**：把原因权重转换成用户线索，并补“用户能否理解、是否误以为官方认证”的可理解性测试。
3. **链接与 Cookie 动作回执**：显示“移除了哪些参数名称”“清理了哪类 Cookie”，不显示对应值。
4. **AI 上下文预览**：摘要前预览字符数、脱敏类别、后端和目的地；结果页明确“启发式/本地模型/降级”。
5. **完整设置页改版**：顶部先放今日/本次会话摘要和健康状态，再放模块开关；活动列表改成分组，可按当前站点筛选。

### P2：有数据和 CPU 预算后再做

1. **可选隐私周报**：只汇总本机计数和类别，默认不弹系统通知；用户可在 Aegis 页开启每周一次浏览器内回执。
2. **更强钓鱼静态信号**：Unicode 同形异义、编辑距离、注册域边界、跨域 form action 和隐藏 iframe；只对中风险页面启用。
3. **第一方标识符关联**：借鉴 CookieGraph/SST-Guard，只关联已标记的可疑同站请求，并设置每页请求、时间和内存预算。
4. **离线规则生成**：WebGraph/PURL/ASTrack/AdGraph 只用于离线生成候选规则，运行时仍使用有界索引查询。

### 明确不做

- 不恢复 Extension，不使用 content script 注入提示条。
- 不用一个无法解释的“0–100 隐私分”代表网站安全。
- 不默认发送系统通知，不对每次拦截弹窗或播放动画。
- 不在普通页面加载路径加入图分析、AST、bytecode、NER 或本地模型推理。
- 不在功能门和出站审计完成前宣称“无遥测”“页面内容绝不外发”或“网站安全”。

## 6. 技术边界与性能预算

### 事件模型

建议结构化为：

```text
document_id | tab_id | profile_scope | site_key
kind | reason_code | display_domain | count | first_time | last_time
```

- 以 `(document, site, kind, reason)` 为聚合键，1 秒窗口内合并。
- 每个 tab 最多保留 50 个事件组，每个 Profile 总内存预算不超过 1 MiB。
- 同一 tab 的用户可见更新最多每秒 4 次；面板关闭时只更新有界计数，不创建 WebUI 页面。
- 页面导航后冻结上一文档并清零当前页计数；tab、普通/无痕 Profile 互不串数据。
- 不持久化 query、fragment、Cookie 值、页面正文和完整跨站跳转链。

### UI 更新

- 盾牌和原生气泡由 Browser UI 读取聚合快照；不让每个网络请求直接触发 UI 重绘。
- `chrome://aegis` 改为事件驱动；至少在 `document.hidden` 时停止刷新，页面恢复可见后做一次增量同步。
- 图标不使用持续动画；首次教学气泡只执行一次短时展示。

### 性能门

- 隐藏状态下 `chrome://aegis` 为 0 次周期性 `getStatus` 调用。
- 1000 个合成事件突发时，内存保持在预算内，UI 更新频率不超过限制，Browser UI 不阻塞。
- Aegis ON 相对 OFF 的正式门继续采用：稳态均值增量不超过 3 个单核百分点或 OFF 基线的 10%（取较大值）。
- 新 UI 在无事件空闲场景不得形成可测的持续 CPU 增量；气泡打开 p95 目标小于 100 ms。

## 7. 分阶段实施计划（确认后）

### U0：事件合同与测试基线（1–2 人日）

步骤：

- 先增加 tab/document/site 结构化事件和聚合器的失败测试。
- 定义类别、原因码、隐私裁剪、内存/频率上限和 Profile 隔离合同。
- 保留现有 `chrome://aegis` 兼容映射，避免一次性重写全部模块。

验证：

- 正例、负例、重复突发、导航、双 tab、普通/无痕和上限测试通过。
- 原始 query、Cookie 值和页面正文不能进入用户可见事件。

### U1：盾牌与当前站点面板（3–5 人日）

步骤：

- 增加 Chromium 原生工具栏盾牌、四类状态和当前页聚合数量。
- 增加当前站点面板、分组详情和“打开完整设置”。
- 增加键盘、读屏、缩放、窄窗口、浅色/深色与中英文文案。

验证：

- 代表性 tracker/param/cookie/bounce fixture 的面板数量与底层事件一致。
- 双 tab 切换、导航和 Profile 隔离正确；图标不把“无事件”显示为“网站安全”。
- Computer Use 完成真实 App 的入口、布局和操作路径验收。

### U2：首次反馈与站点级恢复（2–3 人日）

步骤：

- 增加一次性教学气泡及已完成状态。
- 增加有时限的站点级暂停、重新加载、恢复默认和清晰的作用域说明。
- 对不可逆动作使用“临时允许并重新加载”，不使用误导性的“撤销”。

验证：

- 教学气泡每 Profile 只出现一次；普通/无痕状态不串联。
- 暂停后对应行为真实恢复，过期或手动恢复后重新启用；不改变全局默认。
- 用户在两次操作内完成站点恢复。

### U3：解释、AI 预览和设置页改版（3–5 人日）

步骤：

- 升级钓鱼线索说明和可理解性文案。
- 增加摘要上下文/脱敏/目的地预览及准确的后端状态。
- 将完整设置页重排为“健康摘要 → 本次会话 → 模块设置 → 高级诊断”。
- 将 2 秒轮询替换为事件驱动或可见性控制的增量刷新。

验证：

- 钓鱼正负例、仅继续一次和解释一致性测试通过。
- mock Ollama 证明预览与最终发送边界一致，失败时准确降级。
- 页面隐藏时无状态轮询，实际 App 无布局与可访问性回归。

### U4：可选周报与论文研究项（每项单独批准）

步骤：

- 先定义本地数据保留、开关默认、CPU/内存预算和研究数据集。
- 每个研究能力独立做离线评估、误报门和真实站点回归；不合并成一个大模型功能包。

验证：

- 周报关闭时无持久化和通知；开启后只包含聚合事实。
- 研究项未通过准确率、性能和隐私门时保持 feature flag 关闭。

## 8. 验收指标

### 用户感知

- 8 人以上内部任务测试中，至少 80% 能在 5 秒内找到当前站点保护状态。
- 至少 80% 能说出一项 Aegis 实际执行的动作，并能区分“防护模块正常”和“网站安全”。
- 站点兼容问题从发现到临时恢复不超过 2 次操作。
- 除首次教学和高风险阻断外，普通浏览每会话 0 个主动弹窗。

### 功能与稳定性

- tracker、filter list、link sanitize、Cookie、bounce、phish 各有正例、负例和关闭状态测试。
- 代表性多站点导航、50 次启动、tab/Profile/无痕隔离、崩溃与 GPU 门继续通过。
- 状态显示必须与真实模块 ready/error/paused 一致，禁止“开关打开即显示正常”。

### 隐私与发布边界

- 用户反馈历史不保存完整 URL、query、Cookie 值或页面正文。
- 所有远端、本地模型和 Chromium 背景出站继续分开披露。
- 本计划完成只代表本地功能与体验门通过，不自动解除当前项目整体 No-Go，不授权 GitHub、签名、公证或发布。

## 9. 实施结果

### 已完成范围

- **U0**：加入 tab/document/site 结构化事件、1 秒聚合、有界存储、隐私裁剪和 10 分钟站点暂停合同；网络、链接、Cookie、bounce 均遵守暂停，钓鱼防护不随站点暂停关闭。
- **U1**：加入 Chromium 原生固定盾牌、当前页计数、站点保护气泡、分组事实和完整设置入口；没有 Extension 或网页注入。
