# Aegis 设置交互改进方案

日期：2026-10-21。状态：待确认方案。本文描述后续改进，不代表已实现；本轮代码仅移除隐私页重复入口、将实验模型独立分类。

## 推荐顺序

先完成鼠标手势的「画出方向 → 选择动作 → 添加并保存」流程，再统一设置反馈，最后整理模型配置。保持现有配置格式和既有绑定，不引入新的识别引擎。

| 优先级 | 改进 | 用户能看到的结果 |
| --- | --- | --- |
| 第一批 | 在练习结果旁添加手势 | 画完直接选择动作并保存，不需要输入 L / R / U / D |
| 第一批 | 已有手势可就地修改 | 画到已有方向时显示现有动作，通过「修改绑定」进入编辑，不创建重复项 |
| 第二批 | 统一保存反馈 | 每个设置明确显示自动保存或手动保存；只有收到后台结果才显示已保存，失败保留输入 |
| 第二批 | 简化共用模型配置 | 摘要与助手使用一处基础连接表单，模型池与路由作为单独区域，避免两处表单互相覆盖的困惑 |

## 鼠标手势：画完即可添加

现状：练习结束后，代码会记住识别方向；点击下方「添加手势」能带入该方向，但仍需在列表选动作，再点页面底部「保存设置」。按钮分散，已有方向也可能被重复加入，最后保存时才报错。主流程不应要求用户理解方向字母。

建议将「先试一试」改为「绘制与设置手势」，保留练习不执行浏览器操作的规则。完成绘制后，在绘图区下方直接展示方向箭头、匹配状态和下一步操作：

1. **未绑定的有效方向**：显示如「↓ → · 尚未绑定」，提供动作选择、作用范围说明、「添加并保存」及「重画」。动作必须由用户选择，不预选后退或关闭标签。
2. **已经绑定的方向**：显示当前动作，提供「修改绑定」和「重画」。修改时显示原动作与新动作；提交更新原条目，不额外添加相同方向。
3. **方向不明确、只有点击、超过 8 个方向或被取消**：显示具体原因，不允许添加，也不沿用上一次成功绘制的方向。
4. **保存成功**：当前绑定立即出现在列表，显示「已保存，下一次手势生效」。保存失败则保留绘制结果和选择，允许重试。

「添加并保存」通过现有原生保存接口提交当前页面的有效配置，按钮旁说明会同时保存本页其他待保存修改，避免用户误以为只保存新增条目。若列表已有错误，定位到错误行，保留绘制结果；不静默丢弃其他草稿。仍保留现有手动编辑入口作为高级方式。

列表中的方向优先显示箭头，动作按导航、标签页、页面、PDF 分组；PDF 专用动作明确标注仅在内置 PDF 阅读器生效。触控板或无法持续按右键的用户，可用方向按钮组成手势，再走相同的动作选择和保存流程。

### 验收标准

- 实际画出一个未绑定方向 → 选择动作 → 添加并保存 → 重启后回读一致；在普通网页验证该动作生效。
- 绘制已有方向 → 修改动作 → 保存后只有一个对应条目，其他绑定与网站例外不变。
- 练习区内画出「关闭标签」等方向，标签仍保持打开；离开练习区的真实手势按已保存绑定执行。
- Esc、失焦、越界、模糊斜线、超过长度限制均不能保存旧轨迹；重新绘制可以恢复正常。
- 保存失败、重复提交、64 条上限、页面已有无效草稿均有清楚反馈，不丢失其他输入。
- 浅色、深色、窄窗口、125% 缩放与键盘操作均检查；按钮保持在绘制结果附近。

## 其他设置整理

**保存反馈**：阅读、实验开关、下载策略等即时保存设置，在当前卡片显示「保存中／已保存／保存失败」。手势等需要统一提交的页面固定显示「有未保存的修改」，离开时可选择继续编辑或放弃。首次读取失败不能显示默认值并冒充已保存配置。

**AI 与模型**：下一批考虑合并共用连接表单，同时保留协议、服务地址、模型列表、自定义模型、密钥状态、保存和清除密钥全部能力。模型池高级参数使用明确的「添加模型／更新当前条目」按钮，路由模式仍可即时保存；整理前先做旧能力对照和密钥保存边界测试。

**实验功能**：本轮先独立 MINIM、PhishLang，保留默认关闭、手动触发与效果限制说明。后续可按实验分别显示用途、是否已启用、模型资源是否可用和如何开始分析，避免把开关开启误解为正在后台保护。

建议先批准并实施鼠标手势这一批，完成真实绘制、保存、重启和网页动作验收后，再处理其他设置。
