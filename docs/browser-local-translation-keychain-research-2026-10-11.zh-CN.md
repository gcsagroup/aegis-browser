# 跨版本钥匙串与本地翻译、研究续验

## 本轮目标

用户明确要求后续不同版本不再因签名变化重复请求钥匙串密码，并继续 MINIM、PhishLang 的真实评测。用户已澄清：本地 AI 翻译引擎应放在本浏览器中，不是 iOS 模拟器。

完成标准：固定身份的真实 App 从 157 升到 158 后读取同一份旧加密资料；研究从人工夹具进入真实标注数据；本地翻译运行真实模型，核实中英双向结果、包体和可集成方式。研究试验与正式产品接入分别记录。

## 跨版本钥匙串结果

- 在同一可执行文件路径编译两个不同版本的独立探针，使用固定 GCSA 证书和同一个签名标识。禁止探针弹出授权窗口后，第二版仍能读取第一版创建的测试钥匙串项；完成后清理了该测试项。
- 真实浏览器在固定路径 `/Users/lazy/Applications/GCSA Aegis Test.app` 从 Ver 3.0 (157) 升到 Ver 3.0 (158)。两版指定签名要求相同，代码内容不同；签名严格校验通过。
- 两版使用同一份 Acceptance Profile。158 无需再次输入密码或处理授权弹窗，读出了五条旧资料；搜索并展开“实机批注152”，原文、引文、批注和工作区名称均一致。资料库密文摘要未改变。
- 构建入口继续固定证书，不允许证书缺失时回退到临时签名。此次修正和验收针对“正常版本升级导致身份变化”的重复授权，不改系统密码、钥匙串锁定设置或已有访问控制。

[Apple 的签名说明](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)指出，钥匙串通过程序的指定签名要求追踪其身份；不能只比较签名验证是否通过，也不能用同版本重启替代跨版本验收。

## 本地翻译的实际结果与推荐

推荐内置受控的 Bergamot 翻译运行时，中英语言包按需下载，下载校验完成后离线使用。保留用户现有模型服务作为另一种可选方式。无需另起常驻 Python 服务，也无需用户填写 API 密钥。

本轮从官方 npm 下载 `@browsermt/bergamot-translator 0.4.9`，核对包摘要；从 Mozilla 发布的模型清单取得中英模型，逐个校验压缩和解压后的 SHA-256。实际在 GCSA Aegis 的本地验证页运行 Web Worker / WebAssembly，页面策略仅允许连接本机资源。

| 语言方向 | 下载体积 | 解压体积 |
| --- | ---: | ---: |
| 英语 → 简体中文 | 36.13 MB | 51.93 MB |
| 简体中文 → 英语 | 47.60 MB | 70.08 MB |
| 双向合计 | 83.72 MB | 122.02 MB |

运行时 npm 包解包约 5.31 MB。以上是十进制 MB，不是内存占用。

六段功能样本在真实浏览器中全部生成译文，包括数字、日期、否定语义与浏览器操作说明。首次载入对应方向分别约 306 ms、295 ms，后续短段约 22–34 ms，六段总计约 714 ms。示例：

- 原文：`Do not close the window until the download is complete. The file size is 12.5 MB.`
- 译文：`下载完成前不要关闭窗口。 文件大小为12.5 MB。`

这些是本机短文本试验，不是长网页性能、跨平台性能或标准翻译质量分数。现有正式阅读面板仍走用户配置的模型服务；158 中尚未把此验证页的引擎接入正式翻译入口。

[Mozilla 当前说明](https://raw.githubusercontent.com/mozilla/translations/main/README.md)明确模型文件使用 MPL 2.0；不要继续引用已归档旧仓库的状态来推断当前语言包不可用。

正式接入建议按以下范围实施：

1. 阅读面板增加“本机翻译”，模型语言包在浏览器界面下载、校验和管理，显示真实可用状态。
2. 翻译任务在独立 Worker 中运行，支持进度、取消、超时和释放模型内存；默认保留原文，逐段显示译文，结果按现有加密库保存。
3. 语言包使用固定来源和摘要清单；网页文本仅作为模型输入，译文以纯文本呈现。先覆盖中英双向，再按实测结果扩展语言。
4. 接入验收覆盖无网络、模型缺失/损坏、长文分段、取消、数字/否定词保真和不同设备性能；不把六段成功作为上线质量门槛。

## MINIM 与 PhishLang 续验

研究数据、模型与运行日志留在 `.artifacts/reading-followup-20261011/`，不并入 App 安装包。

- MINIM 数据集固定到 `fd1786cb08dc42173905588e7ca015de968c8134`，数据卡标注 MIT；代码仓库固定到 `456c60b6fd47941d1e5849db573dbbcb488e3ae7`，仍未发现代码许可或现成评分器权重。数据许可和代码许可须分开表述。
- PhishLang 仍使用此前核对的 MobileBERT 权重；另从 [PhreshPhish](https://huggingface.co/datasets/phreshphish/phreshphish) 固定提交 `eabec4b7a66324b79cc8a0ad856d1731dc26fe1a` 的首个测试分片抽样。只解析静态 HTML，不访问样本网址。该数据集标注 CC BY 4.0，限定反钓鱼研究；这不补足 PhishLang 模型自身的许可。

### PhishLang 的真实数据结果

固定种子从首个测试分片的 1,000 条记录中抽取 120 条；不根据预测结果选样。66 条因超过 8,192 token 的试验预算排除，另 8 条因大小/重复/标签检查排除，最终评测 46 条：31 条钓鱼、15 条正常网页。该样本具有长度筛选和分片偏差，不能外推到整个数据集；尚未与上游训练数据查重。

| 实现 | 正确识别钓鱼 | 漏报 | 正常网页误报 | 正确识别正常 |
| --- | ---: | ---: | ---: | ---: |
| 上游原窗口实现 | 27 | 4 | 14 | 1 |
| 补齐短输入和尾部 | 29 | 2 | 14 | 1 |

补齐窗口让两条原本没有被正确识别的短钓鱼样本进入模型并被识别，但正常网页误报仍然很高。结论是**当前权重和 0.5 阈值不适合直接作为默认自动拦截器**。这是本机试验结果，不是否定论文全部结果；正式接入前需要独立验证集做校准，并在另一个未使用的测试集验收。模型许可也仍未明确。

### MINIM 的真实数据评分器

从 150 个原始页面各固定选取三个任务变体，共 450 条。以原始页面为分组单位分为 120/15/15 个训练/验证/测试页面，对应 360/45/45 个变体，三组没有页面重叠。MLP 基线已真实训练十轮并保存权重；GATv2 使用同一分组和固定十轮训练，MiniLM 特征模型从已核对的本地文件加载，训练与评测均离线运行。

MLP 在留出的 45 个变体、65,772 个节点上，仅保留了 8,574 个必要节点中的 217 个（2.53%），且 1,326 个敏感节点仍有 94 个原文暴露（7.09%）。固定的上游阈值为必要性 1、敏感性 5。这个小样本训练结果不能纳入浏览器：大量删除虽缩小观察范围，却破坏了任务所需内容。数字是我们定义的节点计数代理指标，不冒充论文的全部指标或实际任务完成率。

GATv2 的训练和留出测试用时约 482 秒。最终在同一批 65,772 个测试节点上全部选择删除，必要节点保留率为 0%，敏感原文暴露率也为 0%。后者来自“什么也不保留”，不能称为可用的隐私保护效果。本轮两种自训评分器均未通过功能准入；现成作者评分器仍未取得，代码许可也未明确。下一轮需要在验证集排查采样覆盖、标签分布和训练配置，并使用新的留出数据验收，不能反复用这批已观察过的测试样本调参。

## 本机复现入口

以下脚本都需要显式指定输入和输出目录；研究运行使用本次隔离环境。模型、数据和上游来源摘要保留在证据目录中。

- `apps/browser/scripts/check-keychain-upgrade.py --output <新的证据目录>`：在 macOS 上创建并清理独立测试钥匙串项，测试固定身份的两个二进制版本。
- `apps/browser/scripts/minim-real-data-pilot.py --source <固定上游源码> --source-sha256 <摘要> --data <标注数据目录> --output <结果目录> --model-type mlp`；GATv2 使用 `--model-type gatv2 --embedding-model <已下载的MiniLM目录>`。
- `apps/browser/scripts/phishlang-real-data-pilot.py --source <PhishLang目录> --rows <静态样本JSON> --sampling <抽样记录JSON> --output <结果JSON>`：只接受固定上游源码摘要，模型加载使用本地 safetensors，不请求样本网址。

本次实机测试后已关闭临时翻译页、停止验证服务，并恢复日常 cnBeta 窗口。系统密码、钥匙串访问控制和日常模型设置均未修改。其他并行任务正在修改的 iOS 文件保持原样。
