# Aegis Browser Agent v2 架構與原型決策

## 決策

Browser Agent v2 停止繼續擴充 v1 執行路徑。保留 Profile 隔離、策略代理、固定原生工具、
核准、稽核以及隱私/反網路釣魚資產，重新實作由瀏覽器掌控的規劃與執行循環。最終選擇
**P4 原生混合方案**：模型負責理解和提出操作，Chromium 負責限定範圍、執行、觀察和驗證。

目前候選原始碼是 Chromium 提交
`c930fa41ef7e9522f145848f3080ee0cc1edc4d8`，由 95 個頂層補丁和 2 個巢狀 V8
補丁重建。這個身分只描述原始碼，不等於已經達到公開發行資格。

## 產品目標

一般使用者只需描述想要的結果，不應先開啟正確網頁、選擇工作流程或學習瀏覽器自動化。
Aegis 必須：

1. 理解目標和使用者點名的網站；
2. 決定使用目前頁面、直接 URL、站內搜尋還是純瀏覽器資料；
3. 產生使用者可見、範圍明確的計畫；
4. 每次只執行一個瀏覽器核准的工具；
5. 觀察真實瀏覽器狀態，必要時重新規劃；
6. 只報告已經由瀏覽器驗證的結果。

模型永遠不會取得瀏覽器通用權限，也不能自行宣布任務成功。

## Runtime 流程

```text
桌面側欄 / Android Agent 介面
  -> 目標路由（原生 agent.route_goal 函數）
  -> 瀏覽器目標解析與 scope 建立
  -> Planner（原生 agent.submit_plan 函數）
  -> PolicyBroker（工具、origin、tab、資料、預算、風險）
  -> 瀏覽器原生工具或綁定文件的 Actor 動作
  -> 觀察與後置條件驗證
  -> 下一次模型呼叫、使用者接管或驗證完成
  -> TaskStore、時間軸和易懂結果
```

### 目標路由

第一次模型呼叫把目標理解為研究、瀏覽器管家、安全下載或購物，並提出入口類型。Chromium
隨後套用確定性約束：

- 明確 URL 保持為 HTTPS 目標；
- 京東、Amazon、GitHub、YouTube 等點名網站使用該站自己的 HTTPS 首頁或搜尋 URL，
  不退化到通用搜尋引擎；
- 「目前頁面/這個頁面」綁定作用中的公開網頁文件；
- 書籤、分頁等純瀏覽器任務不會開啟搜尋頁；
- 發現和比較預設為唯讀研究，只有使用者明確要求購買操作時才進入購物權限。

### 規劃與執行

Planner 只接收目標、已解析目標、資料類別、預算，以及瀏覽器已經核准的工具。它必須回傳
一個嚴格的原生 `agent.submit_plan` 呼叫。每輪執行只能呼叫已登錄工具，且 schema、
風險、tab、origin、DocumentToken 和預算必須全部通過策略檢查。每次動作後，Runtime
把有界結果交回模型；導覽或使用者接管後必須重新觀察。

### 格式恢復

本機或雲端模型可能產生內容基本正確、但函數參數格式不合格的結果。v2 允許一次由瀏覽器
產生的修復呼叫，其中只包含被拒絕的 schema 錯誤。修復只能改格式，不能擴大工具、origin、
資料、風險或預算。如果兩次規劃都失敗，Chromium 僅能為白名單內的 R0 唯讀目標產生
最小恢復計畫：頁面觀察/擷取、書籤列出/檢查/預覽、官方下載來源發現，或分頁/視窗
中繼資料。購物、寫入、表單和外部副作用絕不走這條恢復路徑。

## 瀏覽器掌控的保證

- 每個一般 Profile 一份服務，其桌面主要無痕 Profile 使用另一份獨立服務；Guest、System
  和輔助 OTR Profile 不啟動 Agent。
- 工具登錄表在編譯期固定；模型不能建立工具，也不能執行任意 JavaScript、shell、通用
  CDP 或本機檔案存取。
- 精確綁定 tab、origin 和文件。導覽會讓舊觀察和舊動作參照失效。
- 密碼、Cookie、OTP、付款資訊、受保護表單值和 API key 不進入模型上下文、任務儲存或
  建置成品。Aegis Actor journal、診斷和 trace 會抑制私密資料；預設 NetLog 擷取會遮蔽
  `x-api-key` 與 `x-goog-api-key`。明確使用 `kIncludeSensitive` 的 NetLog 仍沿用 Chromium
  的敏感資料語意，可能包含秘密。
- 一般 Profile 的模型憑據由瀏覽器憑據機制儲存，並按 endpoint 隔離；無痕憑據只存在於
  工作階段記憶體。loopback 可使用 HTTP，遠端模型 endpoint 必須使用支援的 HTTPS。
- R0 唯讀動作可在任務確認範圍內執行；R1 可逆動作保持有界；R2 寫入或外部副作用需要
  精確 action 核准；R3 結帳、付款和最終提交必須由使用者接管。
- 是否完成由瀏覽器後置條件決定，不採信模型自然語言聲明。

## 桌面無痕隔離

桌面主要無痕服務獨立持有 Agent Runtime、目前頁面摘要、`chrome://aegis` 控制介面、任務
狀態、Actor 和隱私事件。路由嚴格使用實際所屬 Profile；無痕服務不會退回一般服務，也不會
寫入一般 Profile。

無痕 TaskStore、模型憑據、自動化狀態、復原憑據、進階下載所有權、事件歷史和已學習的
CNAME 別名都只存在於記憶體，會隨無痕工作階段結束而清除。歷史記錄搜尋只讀取該無痕
工作階段內的導覽記錄。Actor 日誌、診斷日誌和 trace 會隱藏私密 URL、頁面/任務資料、
目標和憑據識別碼；無痕登入品質記錄不會上傳，無痕監控也不會傳送系統通知。

使用者明確核准的書籤修改和已完成下載是例外：它們保留 Chromium 原生、使用者可見的
持久語意，可能在無痕視窗關閉後繼續存在。關閉無痕工作階段會取消仍在進行的 Agent 下載
和種子傳輸，撤銷任務控制權，並保留已經寫入的種子位元組。種子所有權只在同一 Profile
工作階段內跨設定頁重新整理保留，進入終態後釋放，且絕不跨 Profile。

處理程序層級 CDP 無法依 Profile 隔離偵錯端點可見目標，因此建立任一主要無痕工作階段
會立即停止並阻斷整個處理程序的所有 HTTP 與 pipe 遠端偵錯傳輸，包括並非由 Aegis 啟動
的傳輸。最後一個無痕視窗關閉後仍維持關閉，只能由使用者在一般 Profile 中明確重新啟用。
每個一般 Profile 都會在初始化時安裝守衛，早於其第一個 Browser 或 renderer。這是刻意
保留的安全邊界，不會停用原生且綁定文件的 Agent。

Guest、System 和輔助 OTR Profile 不會收到 Aegis 介面/服務，也不會安裝其網路 throttle、
指紋保護或過濾清單設定。一般與主要無痕 Profile 使用不透明且不同的網路分區識別碼，
已學習的 CNAME 別名不會跨 Profile，並在 Profile 關閉時移除。

## 使用者介面

桌面端一般與主要無痕 Profile 都使用明顯的固定 Agent 按鈕和側欄。Android 使用明顯的
瀏覽器入口、常用目標底部面板和完整 Agent 任務頁。兩端共用目標模型、任務時間軸、
provider/model 狀態、易懂的恢復提示和常用情境：

- 摘要目前頁面；
- 比較商品；
- 預覽後整理書籤，並支援復原；
- 檢查書籤 URL；
- 尋找安全的官方下載；
- 研究主題或使用者點名的網站。

自動化從「進階設定」中獨立出來。預設包括降價、到貨、網頁變化和 URL 有效性，支援
每 15 分鐘、每小時、每 6 小時、每天或每週。自動化只在瀏覽器可執行時排程，使用有界
重試和退避，並可暫停或刪除。

## P0–P4 原型比較

| 原型 | 形態 | 優點 | 阻斷問題 | 結論 |
|---|---|---|---|---|
| P0 | 只做提示詞聊天/搜尋 | 最快形成介面 | 把所有需求當文字或搜尋，沒有可信執行循環 | 淘汰 |
| P1 | 擴充功能/CDP 外部 Agent | 迭代快 | 權限過寬，Profile/文件生命週期弱，產品融合差 | 僅研究 |
| P2 | WebMCP/純 DOM Agent | 頁面工具結構化 | 無法完整管理原生書籤、下載、分頁、隱私和反網路釣魚狀態 | 只作為元件 |
| P3 | 純 Chromium Actor Agent | 頁面動作綁定強 | 單獨無法涵蓋瀏覽器原生資料和生命週期 | 只作為元件 |
| P4 | 原生混合 Runtime | 在同一策略/驗證器下組合模型、Actor 與瀏覽器原生工具 | 整合與跨平台測試成本最高 | **選用** |

P4 是滿足「理解、規劃、執行、觀察、驗證」的最小完整設計，同時不會把模型變成高權限的
遠端瀏覽器控制器。

## 平台與驗收邊界

macOS、Windows 和 Android 必須從同一候選原始碼建置，並記錄成品雜湊。Android 必須
安裝到指定 Pixel 實機；Windows 必須在指定 Windows 主機上建置並實際操作。iOS 明確
不在本輪 v2 實作範圍內。

驗收必須真實檢查：入口可發現、不預先開啟頁面的任務、模型規劃與一次有界修復、頁面摘要、
點名網站路由、書籤、下載、定時任務、隱私保護、反網路釣魚、新手可讀錯誤、一般/無痕
隔離、憑據/瀏覽資料不洩漏，以及精確原始碼/成品身分。只有原始碼建置或單元測試通過，
不能取代跨平台產品驗收。
