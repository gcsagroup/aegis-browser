# GCSA Aegis 设置与内置页面整改开发计划

日期：2026-09-13。

**状态：已完成本轮本地 macOS 实施与验收，最终版本 Ver 1.1 (018)。逐项结果见[验收记录](ui-copy-acceptance.zh-CN.md)。**

依据：[设置与内置页面检查报告](ui-copy-audit.zh-CN.md)，包含 UI-01 至 UI-26。

## 目标与交付范围

让设置页、内置页和 AI 助手中的文字准确、一致、易懂：产品身份统一，状态与实际行为一致，数据去向清楚，主界面不再展示开发测试步骤。

覆盖 13 个设置主页面、相关子页和弹窗、新标签页、历史记录、书签、扩展程序、下载中心、防护中心、工具栏防护面板及 AI 助手。补查密码管理、导入、无痕、证书错误和钓鱼拦截页面，发现的同类文案问题纳入本次整改。

交付包括：产品改动及可重放补丁、英文/简体/繁体文案、更新后的检查清单、针对实际行为的测试、固定路径的 macOS 测试 App、实机验收记录和剩余问题说明。

本次定位为现有功能纠错与界面整理，不引入账号同步服务、新模型服务、新的后台更新安装器或新的遥测系统。以 macOS 实机验收为完成目标；共享资源需检查跨平台条件，Windows、Android 未完成实机测试时明确标记，不宣称跨平台验收通过。

## 需要随本计划一起确认的产品决定

| 项目 | 推荐决定 | 行为影响 |
| --- | --- | --- |
| 产品名称 | 用户界面统一为 `GCSA Aegis` | 名称与标题调整；保留现有内部地址、设置键、应用标识及安装包匹配规则 |
| AI 功能名称 | 中文统一“AI 助手”，完整名称为“GCSA Aegis AI 助手” | 将 Agent、智能体等混用名称归一；保留必要的第三方产品和协议名 |
| 重置报告 | 在 GCSA 构建中移除上游报告勾选项，并阻止对应的 Google 重置报告发送路径 | 重置浏览器设置时不再向该上游报告接口发送设置报告；不影响安全浏览等独立功能 |
| 未接入的上游功能 | 确认当前构建确实不支持后，隐藏其入口；暂时不可用或由策略禁用的功能说明原因 | 清理无效的增强自动填充、同步相关引导等，不以“按钮灰色”作为删除依据 |
| 第三方服务 | 保留实际使用的 Google 搜索、Google 翻译、Chrome 应用商店及安全服务的真实名称和数据说明 | 不将第三方能力冒充 GCSA 自有能力，不修改用户选择的默认搜索引擎 |
| 防护与高级设置 | 主页面保留功能与关键影响，开发参数、规则命中细节和测试步骤移入详情 | 保持当前默认开关和用户设置；暂保留策略处理开关，仅调整名称和位置 |
| 更新与模型状态 | 依据真实状态显示，不用“尚未发现更新”推导“最新版”，不用“已保存配置”推导“已连接” | 修正状态语义；不新增打开页面即发送模型请求的行为 |

已明确包含的行为修正为：产品更新状态共享、模型状态显示、GCSA 重置报告关闭，以及经代码确认不支持的入口整理。如补查发现需改变防护算法、数据保存策略或第三方服务接入，记录为新事项，在扩大范围前另行确认。

## 阶段 0：补齐检查与锁定修改清单

对应：UI-05、UI-08、UI-09、UI-12、UI-14、UI-26，以及上轮尚未实机覆盖的页面。

工作：

1. 核对当前工作区、已有未提交修改、补丁序列、测试 App 版本和构建路径，保留其他进行中的工作。
2. 恢复原生窗口读取，补查密码管理、导入、无痕页及相关菜单。证书错误与钓鱼页使用受控测试场景，仅观察警告和文字，不越过安全警告。
3. 梳理设置页面、子页面和条件入口，建立“页面—文案来源—可用条件—三语—验收状态”清单。
4. 确认 Google 相关入口属于真实服务、未接入功能还是仅在特定条件下可用，再决定保留、隐藏或改写。

验收：已知 26 项均有处理项；补查项有实际结果或明确阻塞原因。新增同类问题有编号，不能以未打开页面作为“无问题”。如原生读取仍失败，继续进行独立的源码工作，实机项目保持待验收。

## 阶段 1：修正状态与数据说明

对应：UI-01 至 UI-05、UI-24。

### 产品更新

- 关于页和安全检查读取同一份 GCSA 产品更新状态，不再将 Chromium 的默认构建状态作为“已经是最新版”的依据。
- 显示产品版本，Chromium 版本作为次要技术信息。安全检查没有结果时显示“尚未检查更新”，提供前往关于页的入口；不因打开安全检查页而另起自动下载。
- 保持已有关于页检查、下载安装包和手动安装流程。关闭页面是否影响下载必须实测后才能删除相关提示。

| 实际状态 | 推荐显示 |
| --- | --- |
| 尚无检查结果 | 尚未检查更新 |
| 检查中 | 正在检查更新… |
| 没有正式发布版本 | 暂无可用的正式版更新。 |
| 当前产品版本与已发布版本相同 | 当前已是最新正式版本。 |
| 本地产品版本高于发布版本 | 当前版本高于已发布的正式版本。 |
| 下载中 | 正在下载更新…，附进度 |
| 校验中 | 正在校验安装包… |
| 下载且校验成功 | 安装包已就绪，请手动安装。 |
| 请求、下载或校验失败 | 明确失败环节，并给出重试入口 |

### 模型与摘要

- 已保存合法配置只显示“已配置模型”。
- 复用现有“检测可用模型”请求，成功时显示“模型列表获取成功”及检测时间。这只证明该接口可访问，不将其称为推理能力验证。切换地址、密钥、协议后清除旧检测结果。
- 首次加载不主动联系模型服务。过期的检测结果不得当作当前在线状态；重启后以配置状态为准。
- 统一“网页摘要”入口。发送前根据实际目标显示“在本机处理”或“发送至所选模型服务”，保留地址、数据范围及现有确认机制。
- API 密钥说明改成“是否需要 API 密钥取决于所选服务”，按实际服务要求显示必填或可选状态。

### 重置与上游入口

- 在 GCSA 构建条件内移除重置报告界面和发送能力，不能只删除文字而保留可调用的发送路径。
- 根据阶段 0 的能力清单隐藏未接入功能，保留真实第三方服务来源及必要数据说明。

验收：更新状态逐项对照；不可达模型地址不显示“已连接”；变更配置不会沿用上一次检测成功；本机和远程摘要文案一致；受控重置测试中不存在该上游报告请求。

## 阶段 2：统一全局文案与品牌

对应：UI-06 至 UI-14、UI-23，以及关于页初始建议。

工作：

1. 统一页面标题、导航、菜单、按钮、占位文字和提示中的品牌称呼。
2. 固定词汇：“AI 助手”“书签”“网页摘要”“磁力链接”“防护中心”；上下文已明确时省略重复品牌名。
3. 修改默认浏览器、新标签页、历史、性能、Cookie、安全及隐私指南的产品身份文字。
4. 关于页采用产品介绍、产品版本、更新状态、开源与致谢的顺序，产品介绍使用“注重隐私与安全的浏览器。”
5. 检查帮助链接实际目的地；保留适用的第三方帮助并标明来源，产品说明链接到真实存在的 GCSA 文档。
6. 保留 Chromium、V8、许可证、第三方服务等真实署名。新版权文字以仓库已有声明为依据，不凭空补充权利主体。

验收：目标页面不再将当前产品称为 Chromium 或 GCSA-aegis；保留项逐条有理由。操作名称在设置、工具栏和内置页中一致；链接可到达且内容适用。

## 阶段 3：整理防护中心、下载与 AI 页面

对应：UI-15 至 UI-24。

工作：

- 防护中心统一为“功能名称 + 一句作用说明”；测试步骤、实现路径和原始规则标记移到诊断详情。
- 防护开关按作用命名。挖矿功能继续明确“仅检测和提醒”；概览继续说明统计不等于网站可信。
- 下载设置改用用户语言；保留准确单位、BT 的 IP 暴露提示和下载完成后停止上传的说明，协议限制和实现细节放入高级详情。
- AI 控制主说明直接交代允许本机工具读取和操作网页，以及读取内容不会自动脱敏；连接方法放到详情。
- AI 助手统一名称，缩短重复介绍，保留自动化只在浏览器运行期间检查等关键限制。
- 调整按钮间距、说明换行及版本信息层级，沿用现有页面组件，不进行整体视觉重设计。

验收：普通视图不再出现 `packages/core`、测试断言和未经解释的内部状态；技术信息仍可在需要时找到；重要的数据去向、功能限制和风险不被折叠隐藏；现有开关、选择器和任务入口仍正常工作。

## 阶段 4：三语、无障碍与测试

对应：UI-25、UI-26，并回归阶段 1 至 3。

工作：使用现有文案资源机制同步英文、简体中文、繁体中文，不另建通用框架。补齐动态状态和读屏标签，修复仅按 `zh` 分流造成的简繁体混用。

| 验证项 | 方法与通过条件 |
| --- | --- |
| 更新状态一致性 | 自动化覆盖未检查、无发布、同版本、较新本地版本、新版本、失败和安装包就绪；两个页面结论一致 |
| 下载收尾 | 回归下载完成、校验失败、页面关闭等场景；不把文件已下载当成升级完成 |
| 模型状态 | 运行已有状态和模型选择测试，增加合法但不可达地址、检测失败、配置变更后清除结果的行为用例 |
| 重置报告 | 后端测试使用网络拦截或请求计数，确认即使收到旧界面反馈参数也不会发送报告；真实重置只使用可丢弃的测试资料 |
| 摘要数据说明 | 受控本机和远程场景检查地址分类、说明和确认流程；不向真实第三方发送用户网页内容 |
| 三语文案 | 检查缺失资源、未翻译文本、简繁混用及品牌保留项；逐语种查看关键页面 |
| 无障碍 | 开关有可读名称和状态；按钮、返回导航及详情标题没有英文模板碎片；可用键盘访问 |
| 布局 | 正常窗口、窄窗口、长模型名、错误提示、进度及空状态不截断关键内容或遮挡操作 |
| 补丁与构建 | 校验补丁顺序、覆盖文件一致性、格式和受影响目标编译；运行仓库相关质量检查 |

测试应检查实际行为，不为单纯换词编写大量与实现逐字对应的测试。此前 85 项 AI 回归通过仅作为基线，实施后须重新运行。

## 阶段 5：固定 App 实机验收与交付

1. 构建前核对现有版本，每次编译或打包递增构建号。若仍以 `Ver 1.1 (003)` 为基线，则首个整改构建为 `Ver 1.1 (004)`；已有更高版本时继续递增。
2. 复用当前 macOS 构建目录、`/Users/lazy/Applications/GCSA Aegis Test.app` 和既定验收资料，核对实际启动路径及版本。不创建多个同名测试 App。
3. 对重置等会改变数据的测试，使用同一 App 的专用、可丢弃测试资料；不重置现有验收资料或用户日常资料。完成后恢复既定验收环境。
4. 使用 Computer Use 实际打开全部计划内页面，核对三语、布局、状态、按钮行为和读屏标签。特殊错误页面使用受控样例。
5. 将 UI-01 至 UI-26 及补查新增项逐项标为已修复、已验证或仍有阻塞，附必要截图、测试结果和具体原因。
6. 更新相关用户说明及英文、简体、繁体变更记录，交付本地可用 App 和改动清单。

没有正式 GitHub Release 时，用受控样例验证更新各状态，同时如实记录真实发布通道的结果；不得用样例测试宣称真实线上升级已完成。Windows/Android 安装包、公开 Release、GitHub 推送和发布不在本计划的本地实施范围内。

## 最终完成标准

- 26 项问题及补查新增项均有明确处理结果；影响状态真实性或数据说明的高优先级问题不得留作“文案已美化”。
- 产品版本、模型配置、模型请求和摘要处理位置的文字均与实际证据一致。
- 设置与常用内置页品牌、三语和读屏名称一致，真实第三方归属保留。
- 对应测试通过，固定测试 App 的实际页面复验通过；只完成代码或编译不能标记交付完成。
- 未通过项目单列，说明原因与影响；阻塞实机检查时保持待验收状态。
