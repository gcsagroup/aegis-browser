## 2. 它解决什么，不解决什么

#166 服务于 Aegis 浏览器内的 Agent：根据任务能力需求，从配置的模型池选择主模型和一个备用模型，并冻结 reasoning effort、输出预算和价格快照；逐次记录快筛、生成、修复和回退调用的用量及成本。

TypeSafe 是可选的目标理解入口。关闭它后，自动路由仍可使用浏览器内置的保守能力要求。仅本地模式针对新路由排除云端候选并绕过 TypeSafe。

本功能尚未接入 Codex 开发任务调度，不会自动调整开发窗口的模型，也不会缩短 Chromium 编译或 CI 时间。当前确定的收益是配置能力和观测能力；省钱、提速和正确率提升均未通过真实配对实验验证。

## 4. 配置热更新的已知行为

必须先安装并运行包含 #166 的浏览器构建；合并代码不会更新已启动的旧程序。之后支持运行时保存模型池、路由模式及 TypeSafe 设置。

| 时点或操作 | 当前实现 |
| --- | --- |
| 新任务 | 使用新配置选择模型，并冻结任务级配置 |
| 目标理解尚未完成 | 设置变化取消待完成的 TypeSafe/目标路由 |
| 模型池、路由模式或固定模型配置变化时，生成请求等待落盘、尚未发网 | 检测旧配置 generation 并拒绝派发；Planning 失败，Running/Reflecting 暂停 |
| 仅修改 TypeSafe 开关或凭据时，生成请求等待落盘、尚未发网 | 取消待完成的目标路由，但不递增模型派发 generation；该生成请求仍可能发网 |
| 生成请求已经发网 | 保存新配置本身不会自动取消该请求，返回结果仍可能推进原任务 |
| 旧任务的下一次调用 | 重新核验目的地授权并读取凭据，仍使用冻结模型/profile |
| 从云端模式切换为仅本地 | 不保证旧云端任务立即停止，也不自动将其迁移到本地模型 |
| 立即停止某任务 | 使用任务取消操作，不能用删除池条目或切换模式代替 |
| 新增供应商协议或修改算法 | 需要代码、构建和浏览器更新，不能仅靠配置完成 |

目的地只要仍满足“当前显式固定模型目的地”或“启用且授权的池条目”之一，就可能继续获准。因此，从模型池删除条目也不一定撤销其固定模型授权。

恢复开发时应优先覆盖“请求已发出后修改配置 → 接收返回 → 下一轮授权检查”的完整服务回归。是否需要全局立即停止云端调用，是待产品决策的新语义，不能在补测试时静默改变。

### R1 必测清单

- [ ] 固定模型、未配置 profile、自定义兼容端点继续可用。
- [ ] TypeSafe 关闭、低置信度、缺失或非法答案、超时均按既有规则处理；仅本地不发起 TypeSafe 请求。
- [ ] 主模型首个规划请求临时失败时最多回退一次；永久错误、格式修复、执行及监控阶段不擅自换模型。
- [ ] 已发网后修改模式、移除模型或更换凭据，核验在途返回与下一次授权，而非只检查设置已保存。
- [ ] 取消及暂停恢复不重复工具动作，不让过期回调推进新的任务执行。
- [ ] 快筛失败、取消、任务创建失败和未返回 usage 的调用保留记录；快筛与任务关联后不重复计费。
- [ ] 缓存输入和推理 token 的子集关系正确；缺失 usage/价格保持未知；数据库恢复不把不完整账目变成完整成本。

## 7. 何时考虑 revert

当前不执行撤销。只有出现可复现、可归因于 #166 的问题，再比较最小修复和 revert 的成本，例如：

- 持续阻塞网络代理的编译、链接或运行，而短期无法通过局部修复解除。
- 出现权限、隐私或不可接受的行为回归。
- 产品明确放弃该方向，并完成对后续提交和持久化数据的影响分析。

回退必须使用独立、可审查的提交/PR，保留既有提交和证据。特别检查任务数据库版本兼容：#166 将 store 版本及 compatible version 提升至 11，旧实现为 8；不能假设回退代码能直接读取已经升级的数据，也不能通过删除用户数据库来完成回退。

任何基线变化后，重新覆盖受影响的代理验证、Review、CI 和适用运行测试。流程以 [DEV CI 指南](ci.zh-CN.md) 为准。
