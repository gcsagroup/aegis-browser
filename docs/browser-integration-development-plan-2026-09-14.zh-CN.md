### M2：让 Agent 只拿必要数据、只报告真实结果

| 编号 | 工作 | 实现落点与验收 |
|---|---|---|
| A01 | 按任务裁剪观察 | 复用摘要脱敏和 Actor；保留授权选区/字段及来源，剔除无关菜单和背景页面，敏感表单不得进入请求 |
| A02 | 约束数据目的地 | 扩展现有 Broker；页面来源、模型 endpoint、数据类别与动作接收方分别核对，任务内允许读 A/B 站不等于允许把 A 的私密内容写往 B |
| A03 | 核验目标是否达成 | 扩展已有 ResultVerifier；检查目标字段与结果，而非仅接受新观察或工具成功标志 |
| A04 | 识别无进展并有限恢复 | 在既有循环中检测重复错误、旧文档和空动作；最多两轮无副作用重新观察/重新规划，仍受总预算限制 |
| A05 | 补原生工具及 WebMCP 生命周期约束 | 工具元数据进入上下文前检查，绑定文档与撤销状态；仍保持 WebMCP 默认关闭，仅用本地夹具验证 |
| A06 | 建立可重复评测 | 适配现有原生工具，借鉴 WebArena-Verified 的确定性评分；本地注入测试覆盖网页、工具描述、返回值与恢复路径 |

设计边界：来源标签和规则不能保证精确追踪经模型改写后的自由文本。第一版采用保守上下文隔离与明确传输审批，不声明完整信息流证明。若现有任务不需要截图，不新增截图采集；已有截图路径必须独立验证裁剪与遮挡。

恢复不得重复执行状态不明的外部写入；优先回读实际结果，无法确认则交由用户处理。用户接管、取消、导航和关闭无痕后，迟到结果不能继续动作。

**M2 通过条件：** 固定场景中未经授权的敏感出站为 0，错误完成报告为 0；真实任务达到下述基线门槛。学习式风险模型只能辅助观察，不能单独放行动作或默默终止任务。

### M3：把现有能力接成完整用户流程

| 编号 | 工作 | 用户可见交付与验收 |
|---|---|---|
| X01 | 三入口界面设计 | 先提供页面保护、研究工作台、任务中心的可点击预览；检查窄侧栏、三语、键盘和读屏，再接真实数据 |
| X02 | 页面保护整合 | 去重展示请求、Cookie、链接、指纹、钓鱼和下载来源事件；确定命中与疑似分开，不拿总数当危险程度 |
| X03 | 多页研究与引用 | 支持 3–10 个用户选择的网页；提取事实、比较与来源日期，引用能回到原文，原文变化时明确提示位置已失效 |
| X04 | 保存与后续变化 | 保存选中研究结果和来源，接入现有收藏/任务存储与监控；新增、暂停、取消、重启恢复及通知去重实测 |
| X05 | 下载来源与任务证据 | 展示官网关联、仓库/发布者、版本、摘要及签名状态；任务结果可展开实际证据和停止原因 |

第一版不新增独立聊天系统、通用向量数据库或全量历史索引。研究结果需要持久化时沿用已有系统加密存储，明确 schema 迁移、删除、容量上限和无痕内存模式。确需新表才增加最小表结构，不为未定功能预留复杂扩展。

保护例外只提供范围清楚的预览和用户操作，不由 Agent 自动关闭保护。监控沿用浏览器运行时调度，暂停/休眠期间没有执行就不显示为连续监控成功。

**M3 通过条件：** 在固定 App 独立完成“选 3 个网页 → 比较并核对引用 → 保存 → 创建变化监控 → 查看实际变化 → 暂停/取消”，同时验证重启、无变化、部分页面不可读和取消后的行为。

### M4：有上限的研究试验

M4 交付为代码原型、独立评测与采用/放弃建议；不默认开启研究性拦截，也不扩大生产权限。

| 编号 | 试验 | 范围与退出条件 |
|---|---|---|
| R01 | MINIM 学习式裁剪对照 | 与 A01 规则裁剪比较，先核验代码/权重/数据许可；仅当额外收益可复现时建议采用，否则保留规则版 |
| R02 | SST-Guard 方法借鉴 | 复用有界第一方收集信号，只观察语义类别；200 站初筛、至少 50 站关键操作，混合业务端点不能直接整站拦截 |
| R03 | 灰区钓鱼模型 | 比较当前规则、轻量文本模型、按需视觉；先整理合法来源及独立划分，再实验，不将模型分数直接用于硬拦 |
| R04 | WebGPU/过滤规则隐私测量 | 测普通/无痕、跨站、跨 Profile 隔离和兼容性；本轮不修改 GPU 驱动或全局缓存机制 |
| R05 | SCAFFOLD 步骤复用小试验 | 最多 3 类只读站点任务、10 个经过验证的模板；每次重新核对来源、文档、期限与权限，不训练或自改策略 |

每项先设固定实验预算和数据范围。初轮无改善或数据/许可不足就停止并保留失败证据，写明缺什么；不无限抓取数据或扩大模型训练。R01–R05 可按价值逐项排序，并在总体 2–3 周试验时间盒内交付现有证据，不承诺所有模型都达到可上线水平。

## 6. 验收指标与测试执行规则

以下为计划目标，实施前在 M0 固定口径；已有问题单列并修复，不静默降低门槛。

| 类别 | 要求 |
|---|---|
| 基础任务 | 30 个任务各 3 次；90 次总成功率目标 ≥90%，同时报告每类成功率与三次均成功的任务比例；失败不靠重试后挑最好结果 |
| 隐私裁剪 | 相同任务/模型下输入量下降目标 ≥30%；成功率下降不超过 2 个百分点仅作扩展评测目标，90 次试验不足以证明该差异，需报告置信区间并增加配对样本 |
| 安全场景 | 100 个冻结场景中合成秘密未经授权出站为 0；补适应性攻击，发现绕过即修复后重跑受影响集和固定负例 |
| 结果核验 | 空点击、旧文档、未落盘下载、目标缺失、状态不明的写入都不得误报完成；模型文本和 HTTP 200 不作完成证据 |
| 性能 | 相对同内核基线，普通导航额外耗时 P95 目标 ≤10ms，空闲 CPU 增量目标 ≤1 个百分点；同时报告设备、样本与波动，模型调用异步执行 |
| 追踪兼容性 | 200 站观察集，至少 50 站关键操作；新增规则导致关键操作失败即禁止默认启用，覆盖正常登录/支付/视频/文档 |
